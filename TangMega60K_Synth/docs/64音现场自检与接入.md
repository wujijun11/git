基线：队长主工程 `b12b59a`（2026-09-18）。本阶段不重写 DDS/ADSR/音色/力度/表情/混音/延迟，不改音量标度，不改公共 V2 接口。原 `rtl/audio/`、分配器和 I2S RTL 保持原样。

## 2. 独立示例顶层

```verilog
live64_system_top u_live64 (
    .clk(audio_clk),           // 队长提供 49.152 MHz
    .rst_n(audio_rst_n),       // 相关模块共用、同步撤销的复位
    .start(selftest_start),    // clk 域，去抖后的启动控制
    .stop(selftest_stop),      // clk 域，去抖后的停止控制
    .start_ready(selftest_ready),
    .busy(selftest_busy),
    .holding(selftest_holding),
    .released_pulse(selftest_released),
    .error(selftest_error),
    .active_count(active_count),
    .i2s_bclk(i2s_bclk),
    .i2s_lrclk(i2s_lrclk),
    .i2s_data(i2s_data),
    .underrun_count(underrun_count)
);
```

该示例已经包含一个原 `audio_system_v2`，因此不能再接到另一个完整音源后面。若队长要在正常键盘工程中加入模式切换，使用下一节的“仅接事件发生器”方式，避免重复实例化整个音源。

没有板卡引脚、PLL、CST 或 SDC。`start/stop` 不能直接连接异步机械按键；同步、去抖、复位和实际引脚由队长/B 负责。I2S 复用原模块：Philips 格式，24 位有符号 PCM，左右各 32 位槽，默认 48 kHz；不引入 PT8211 模式。

## 3. 控制器端口及确定语义

所有信号处于同一个 clk 域，事件仍采用 V2 ready/valid 握手。

| 端口 | 语义 |
|---|---|
| start | 上升沿请求，只在空闲且 start_ready=1 时接受；持续高电平不会自动循环 |
| stop | 电平有效，运行时锁存停止请求；停止与启动同拍时停止优先 |
| start_ready | 空闲、active_count=0、event_ready=1 且 stop=0；不是输入去抖器 |
| busy | 从接受启动起到所有尾音回收完毕为止；不仅表示正在发送事件 |
| holding | 64 条按下事件已被分配器处理且 active_count=64，正在保持；不表示包络已稳定 |
| released_pulse | 所有配对松键已交接、分配器恢复可接收且 active_count=0，单拍脉冲 |
| error | 非法启动/分配故障的粘滞标志；复位或下一次合法启动清除 |
| active_count | 接原分配器的占用计数，包含尾音 |
| allocation_error | 示例接 full_pulse OR done_error_pulse；运行中发生则请求中止并置 error |

默认固定 `SOURCE_ID=63`、`BASE_NOTE=36`、`VELOCITY=100`、音色 0。按顺序发送 MIDI 36..99，64 个不同音高，共用一个来源是 V2 允许的。source 不等于 voice，声部编号仍完全由队长分配器决定。

参数限制：BASE_NOTE 只能是 0..64，VELOCITY 必须是 1..127；这是固定 64 音发生器，不要改为 0 力度后期望产生按下。改变音符范围或力度后需同步更改频谱测试配置和验收幅度。默认配置的静态频率表由分析脚本生成。

### 重复启动与停止

- busy 期间的 start 上升沿忽略，不排队、不重新触发现有音符；想再次自检，等待释放完毕后先撤销 start，再给一个新的上升沿。
- 在空闲但条件不满足时请求 start，置 error，不发送事件；条件满足后需重新给启动上升沿。
- 已经 valid=1 的事件在 ready=0 时，所有负载和 valid 必须保持，包括收到 stop 时。这意味着停止可能还需交接一条已经呈现的 note-on，再为它发送 note-off。
- 控制器只对实际握手完成的 note-on 逐一发送配对 note-off；即使启动只完成一部分，也不发送未经触发音符的松键。
- 发送完最后一个 note-off 后进入 DRAIN，等待 active_count=0；不能用固定延时猜测尾音何时结束。
- 反压可以无限延长停止完成时间。这是接口尚未接收事件，不是允许丢事件的理由。`released_pulse` 只保证声部回收，不能保证下游 I2S FIFO 中的最后几帧已经播放完。

### 复位

复位可撤销未交接事件，但必须协调复位控制器、事件队列、分配器和音源。**不能单独复位自检发生器而让音源继续运行**，否则会遗失需要松开的音符记录。复位后不自动恢复或重播上次自检。

## 4. 接到正常键盘工程时的必要条件

正常事件入口与诊断入口不能同时直接驱动 `event_*`。队长的模式仲裁应完成以下步骤：

1. 阻止新的普通 note-on，处理已有普通 note-off，排空上游队列并等原声部和尾音清空。
2. 确认没有已接收但未处理的旧事件，再独占切换到自检事件流；把 source 63 保留给诊断，或统一修改来源分配。
3. 将全局表情明确提交到 gain=2048、bend=0、vibrato=0，等待平滑稳定；禁止传感器/App在自检期间覆盖。独立示例通过公共复位和固定中性输入满足这一条件。
4. 使用现有默认 FX_ENABLE=0 的干声音源。原 V2 没有实时效果器旁路字段，不要偷偷添加一个公共端口；在 FX_ENABLE=1 的另一个编译版本中运行本频谱验收无效。
5. 自检停止后，持续保留诊断入口所有权直到 busy=0/释放完成，再返回普通输入。不能在 note-off 被反压时提前切换多路选择器。

模块没有增加全音停止公共指令，也不负责替键盘/App清理所有其他来源。由于 V2 没有逐事件“已分配/已拒绝”应答，64 音成立依赖空闲起步和独占运行；出现 full_pulse 时将本次测试标为失败，不能把发出 64 条事件误报为 64 声部成功。

## 5. 频谱采样和判定方法

- 正弦音色 0，力度 100，中性表情，FX_ENABLE=0，原 PAN_SPREAD=1、MASTER_SHIFT=1 不变。
- 最后一个音分配完成后，再等待 6000 个 I2S 帧，即 125 ms。实际 RAM 检查 64 声部均处于 SUSTAIN，包络=0x600000；不只看 active_count。
- 从真实 I2S bclk/lrclk/data 独立解码 24 位左右 PCM，逐帧与原 sample 握手数据比较，并检查一位延迟、32 位槽和填充位。
- 连续采集 262144 帧，48 kHz 下长 5.461333 秒。最接近的两个目标是 MIDI 36/37，相隔约 3.89 Hz；真实 FFT 栅格间隔为 0.183105 Hz，足以分开其 Hann 主瓣。
- FFT 使用 Hann 窗，按窗的相干增益修正幅度，去掉 DC。4 倍补零只细化读数到 0.045776 Hz，**不把补零说成提高了真实频率分辨率**。
- 左右两路分别验证 64 个独立目标：必须存在局部峰、频率距量化目标不超过 0.20 Hz、幅度为既有增益/包络/力度/声像预测值的 0.8..1.2 倍、相对附近背景至少 20 dB。
- 满幅码 8388607/-8388608 的触碰或越界次数必须为 0；另外报告峰值 dBFS、RMS、DC。该阈值表示本场景下未数字削波，不是所有参数组合永不削波的证明。
- 频率表包含十二平均律理论频率、实际 32 位 FTW 量化频率和量化误差。FFT 峰误差不等于 DDS 本身量化误差。

注意：这是同时发声的 64 个音，不是轮流测 64 次单音再拼频谱。所有样本都是 HDL 计算输出，没有读取预录音频来替代实时合成。

## 6. 复现命令

从 TangMega60K_Synth 工程根目录的 PowerShell 执行（路径按本机安装修改）：

```powershell
./scripts/test-live64.ps1 -ModelSimBin 'C:/modelsim/modeltech64_10.6e/win64' -PythonExe 'python'
```

需要可用的 ModelSim、Python 3 和 NumPy。脚本先运行新增控制器/针对性/长采样测试，执行 FFT 和分析器负例检查，再运行原 `test-audio.ps1` 与原 `test.ps1`。若仅重跑新增部分，可加 `-SkipBaseline`；该输出不能称为完成了本次基线回归。

每次 ModelSim 新建隔离临时目录，避免旧库假通过。每个测试台都有超时、失败断言、test_passed 标志；脚本检查退出码和完成标志。成功采样才执行 FFT，失败退出不能拿旧 PCM 充当通过结果。结果回拷 `sim/live64_results`，不会自动删除临时目录。

已有本次 PCM 后，单独重做分析：

```powershell
python scripts/analyze-live64.py --results sim/live64_results --rom rtl/audio/rom
python scripts/test-live64-analysis.py
# 仅重新生成默认频率表，无需先有 PCM：
python scripts/analyze-live64.py --table-only --results docs/live64
```

综合：

```powershell
& 'C:/Gowin/Gowin_V1.9.12_x64/IDE/bin/gw_sh.exe' scripts/synth-live64.tcl
```

该综合不运行布局布线、不附加猜测的板卡引脚、不修改共享高云库。所有新增现场功能使用可综合 HDL；Python/CSV/FFT 仅用于离线验收。

## 7. 输出文件与待实测边界

`sim/live64_results`：modelsim.log、pcm_live64.csv、capture_meta.json、frequencies64.csv、fft_peaks64.csv、fft_summary.json、spectrum64.svg、analyzer_tests.json。综合日志和资源报告另随交付保留。

仿真只验证数字逻辑和数字 PCM。**DAC 模拟输出频谱、噪声/失真、真实采样率和时钟误差、板级信号完整性、上板延迟及试听全部待实测。** 队长完成 PLL/CST/SDC/板级接线后，用相同的 64 音模式，确认采集设备未削波、录音采样率和通道正确，再对 DAC 录音做独立标定分析；不能把数字 PCM 的 0.20 Hz 容差直接当作未经校准声卡的实测指标。

本阶段实跑数字、综合资源与剩余事项见《64音自检验证记录.md》。
