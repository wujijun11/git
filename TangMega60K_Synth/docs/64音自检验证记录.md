# 64 音现场自检与频谱：实际验证记录

日期：2026-09-19。远端基线：`b12b59a`。功能分支：`feature/liujiakun-live64-selftest`。

开始时 Git 工作区干净，已获取远端最新工程，并保留旧功能分支。没有修改已合入的 DDS/ADSR、波表、力度、表情、混音、延迟或公共 V2/I2S RTL；无新增 PT8211 模式，无板卡引脚猜测。现场发生器经 event 接口进入原声部分配器。

## 1. 验证环境

- ModelSim SE-64 10.6e，新增工程统一 `vlog -sv` 编译，保留队长对 mixer 标识符的修正。
- Windows PowerShell；Python 3，NumPy 2.3.5。FFT 不依赖绘图库。
- GOWIN V1.9.12 x64，GW5AT-LV60PG484AC1/I0。
- 时钟标称 49.152 MHz，48 kHz，Philips I2S 24 位/声道、32 位槽。长采样测试使用 1 fs 时间精度的仿真时钟，避免粗时间单位造成明显采样时钟误差。

复现入口见《64音现场自检与接入.md》。本记录描述实际运行结果，不把生成了脚本当作完成测试。

## 2. 可综合发生器与针对性回归

### 发生器独立测试：PASS

`tb_live64_source.sv` 使用确定性伪随机 ready，计分板逐次检查所有握手事件的内容、顺序及配对。

- 64 个不同启动中止位置（接受 0..63 条 note-on 后中止）。每次先人为拉低 ready，确认未完成握手的 note-on 不被撤销；恢复 ready 后包含这一条在内逐一释放。
- 完整 64 音保持、note-off 反压、尾音结束前 busy 保持。
- 启动过程和保持过程重复 start，不重复发送事件；start 持续高时不自动重启。
- start 与 stop 同拍，停止优先。
- 未清空声部时启动拒绝并置 error。
- note-on 受阻、note-off 受阻、DRAIN 阶段协调复位。
- allocation_error 故障中止及 error 粘滞报告。

最终测试输出：

```text
LIVE64 SOURCE PASSED stop_positions=64 full_run=1 scenarios=65
stalled_cycles=1130 reset_and_fault=covered
```

`scenarios=65` 计数覆盖 64 个停止位置和一次完整保持/停止；复位、非法启动和故障检查另行执行，不包括在这个计数中。

### 真实分配器 + 原音源针对性回归：PASS

`tb_audio_edgecases.sv` 不绕过分配器，以额外握手门控模拟下游暂不可接收，且 valid/ready 两侧同步门控，避免伪造单边握手。

- 分配器已有待发命令但音源未接收时发 stop；最终准确产生 2 次按下、2 次松开和 2 次完成。
- 真正 64 声部同时保持后完整回收；运行中重复 start 不产生下一轮。
- 起音仅经过很少的帧就提前松键，检查提前结束而非强制完整满幅释放时长。
- 同一仍按住音符连续快速重触发 32 次，检查声部计数不增加，实际状态 RAM 的相位和包络值在重触发写回时保留。
- 固定保持一个其他来源的音符；同音高快速 note-on/off 32 轮，阻塞 done 接收，检查 32 个尾音完成通知完整保留。解除反压后恰好回收 32 个，另一个保持声部不受影响。
- PCM 反压时保持样本与 LFO；连续发送 26 个表情包，检查最后 gain=3072、bend=300、depth=40 能经原平滑器到达，不重触发音符。
- 命令、样本、完成三个接口的反压稳定性；受阻输出时协调复位清空声部和样本。

```text
AUDIO EDGECASES PASSED held_retriggers=32 rapid_tails=32
expression_packets=26 start_stop_cmd_stall=covered reset=covered
```

开发中修正了新测试台自身的启动/停止驱动时机：不能在 start_ready 已变化后发送一拍 start，也不能将多等一拍已接受的 note-on 算作重复事件。相应边界已纳入最终测试；未发现需要改变既有音源算法的缺陷。

## 3. 同时 64 音的 I2S 采集

音符 MIDI 36..99，理论基频范围约 65.406391..2489.015870 Hz。64 声部同时保持，正弦音色、力度 100、中性表情、延迟关闭。末音分配完成后等待 6000 帧，并检查所有声部已进入保持阶段。

```text
LIVE64 SPECTRUM CAPTURE PASSED samples=262144 i2s_frames=271875
steady_underruns=0 on=64 off=64 done=64
```

- 采样段长 5.461333 秒，不含启动、起音和衰减过渡。
- 独立串行接收器实际检查 271875 个 I2S 帧，比较其还原 PCM 与发送器接收的 PCM；不是直接把内部正弦模型写入文件。
- 采样段持续检查 active_count=64、held_mask 全 1。
- 预热前启动空 FIFO 共 1 次；之后统计窗口内新增欠载 0。
- 停止后收到 64 条 note-off、64 条 done，active_count=0；再等待 8 帧确认干声归零。

## 4. FFT 与削波结果

Hann 窗；实际 FFT 分辨率 48000/262144=0.18310546875 Hz；4 倍补零只细化读数，不增加真实分辨率。左右分别判定频率、局部峰、预测幅度和局部背景对比度。

| 指标 | 实测仿真结果 |
|---|---:|
| 左声道目标谱峰 | 64/64 通过 |
| 右声道目标谱峰 | 64/64 通过 |
| 最大 FFT 峰频率读数误差（对量化 FTW 频率） | 0.02276525 Hz |
| 所有峰测量幅度/理论幅度 | 0.99006029..1.00001080 |
| 最小局部峰/背景对比度 | 58.20970 dB |
| 左声道最小/最大样本 | -439590 / 501206 |
| 右声道最小/最大样本 | -437316 / 500270 |
| 左声道峰值 | -24.47347 dBFS |
| 右声道峰值 | -24.48971 dBFS |
| 左/右数字削波或越界样本数 | 0 / 0 |

原保守增益与声像完全不变；没有为了让频谱好看而提高/压低测试音量。这个局部峰/背景数值不是 THD+N 或整机 SNR 指标。

频率表有 64 行；`fft_peaks64.csv` 有 128 行（左右各 64）；`fft_summary.json` 包含判据、统计值和失败列表；`spectrum64.svg` 标明全部理论目标。PCM CSV 第一列从 0 连续到 262143，分析器检查丢行、重复行和顺序。

分析器也用独立合成的数学样本做正负例验证：完整 64 音应通过；去掉最低音、整体幅度错误减半、全静音、仅一个样本触及满幅码均应失败。五项全部通过。这些合成夹具仅验证分析脚本，**不拿来作为 RTL 的 64 音证据**。
