## 工程入口及剩余边界

正常音源继续打开 `AudioEngine_V2.gprj`，顶层 `audio_system_v2`。64音独立诊断打开 `Live64_Diagnostic.gprj`，顶层选择 `live64_system_top`，或从工程根目录执行 `gw_sh scripts/synth-live64.tcl`。该诊断工程复用原音源，不是第二套合成算法。

诊断源尚未切入正常键床演奏入口。将来整机切换时必须实现入口独占、普通音符和尾音清空、中性表情及自检释放完毕后的控制权交还；不能直接并接两个事件源。

本次未重新综合或布局布线；队员原综合报告不等于本次合并版时序验收。仍未完成PLL、真实CST/SDC、板级输入同步/去抖、DAC模拟输出及真实延迟测试。所有频谱均为数字仿真证据，不是DAC实测结果。

## 已保存波形的加载

在 ModelSim Transcript 中指定工程目录，再运行固定脚本（队友请替换为自己的路径）：

```tcl
set live64_project_root {C:/Users/asus/Desktop/Git/TangMega60K_Synth}
do "$live64_project_root/sim/view_live64_wave.do"
```

脚本会查找 `sim/live64_results/wave_*/checked.wlf`，选择最新且同目录 `summary.txt` 含有 `test_passed=1` 的记录。显式工程路径原样传给文件API，不依赖当前目录、`info script` 或旧版Tcl的路径规范化。不要直接使用 `dataset open ./checked.wlf`；该相对路径取决于 ModelSim 当前工作目录，容易产生 `file not found`。

WLF和其他仿真产物仍保留在本地忽略目录，不随Git上传。新克隆中没有波形时脚本会明确提示缺少完成记录；本脚本只查看既有结果，不执行仿真。普通完整音源的新仿真与波形生成继续使用 `sim/waves_audio_v2.do`，其结果属于另一组测试台，不能作为本Live64脚本的输入。
