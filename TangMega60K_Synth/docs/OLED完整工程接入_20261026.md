# 四针OLED接入完整演奏与学习工程

本版把已有OLED驱动接到 `board_contest_full_top`，使用与主工程相同的49.152MHz时钟，独立I²C总线。Windows 1.5.0、手机、C3不需要为显示功能更新。旧LearningMode位流没有OLED输出，需使用本次通过构建检查的新位流。

## 屏幕与接线

适用于此前选择的0.96英寸、128×64、四针 `GND/VCC/SCL/SDA`、SSD1306/SSD1315兼容I²C屏，默认7位地址0x3C。四针并不能单独证明控制器型号；若实际为SH1106或0x3D地址，需要按屏幕资料调整，不能宣称所有四针OLED通用。

**全部断电后接线，按接口编号和丝印，不能按照片左右数孔：**

| OLED丝印 | FPGA底板位置 | 说明 |
|---|---|---|
| GND | 公共GND，例如J9-3/4或已分线的J13-12 | 可与MPR/C3共地 |
| VCC | J9-1或J9-2的3.3V，经可靠分线 | 当前屏幕选型允许3.3V；不要接AHCT灯板的5V端子 |
| SCL | **J13-15** | FPGA球位 **A20**，新端口oled_scl |
| SDA | **J13-16** | FPGA球位 **B20**，新端口oled_sda |

这两根数据线紧接原LED数据的J13-14之后；实际仍先辨认J13与pin1，不能混成另一个J14。已有转接底板把15–40脚保留NC，没有替你接出OLED，因此不能假设老转接板上已经有OLED插口。

SCL/SDA为开漏，只拉低或释放，需上拉到**3.3V**。多数模块自带上拉，先按模块电路核对；没有时各加约4.7kΩ到3.3V。用3.3V供电可避免模块上拉把5V送入FPGA。保持线短且可靠，电源、地线有固定连接。不能将OLED总线并到MPR121总线上。

## 引脚核对依据

采用工程内已保存的原始原理图图片，沿60K核心→BTB→31005底板逐级核对：

| OLED | 30353/30354核心球位 | 核心C2399/底板J1接触点 | 31005底板网名 | 外接排针 |
|---|---|---:|---|---|
| SCL | A20，BANK2 | 11 | SDRAM0_D11 | J13-15 |
| SDA | B20，BANK2 | 13 | SDRAM0_D10 | J13-16 |

两版60K核心在这两路相同。参考图位于 `hardware/wiring31005/core30353_p1.png`、`core30354_p1.png`、`neo31005_p7.png`、`neo31005_p19.png`；不是把138K球位直接套给60K。工程既有CST未占用A20/B20，本次增加两路LVCMOS33开漏GPIO。

这仍属于原理图映射；现场的排针方向、供电电压和实际导通需要核对。J13与SDRAM0共享，不可同时装SDRAM扩展模块。

## 上电后会显示什么

屏幕上电等待约100ms后初始化，随后显示四行：

1. 当前页面名称，或“总模式选择”。
2. 四个分区选项，当前区域反显。例如音色页显示“钢琴/风琴/正弦/FM”。
3. 录制、播放、指引、忙碌或菜单错误状态，以及事件数。
4. “长按左端返回”。

滑条最左端长按约1秒再松手进入总菜单；短触某区域并松手进入子页面，长按返回。总菜单四类仍为音色、音区、录放、曲谱。软件修改音色/音区后，已有板上实际状态决定反显。

默认I²C为100kHz，每个显示数据字节独立事务，全帧约0.3秒量级，因此屏幕变化会晚于按键音频，不拿显示刷新时间作为演奏延迟。每帧先锁存状态，更新中不会混入半页新状态。黄蓝屏的颜色分区由屏幕硬件决定。

学习模式继续由灯板和Windows显示具体目标；OLED将其归为“指引中”，本次不新增逐音键号、完成步数或教学评分页面。

## 模块与边界

| 文件 | 本次职责 |
|---|---|
| `rtl/board/board_contest_full_top.v` | 接出实际menu_*状态，实例化独立OLED驱动，新增两根板级端口 |
| `rtl/visual/oled_status_display.v` | 既有初始化、帧快照、I²C事务及NACK重试，算法未改 |
| `rtl/visual/oled_menu_renderer.v` | 既有中文菜单/字模和选项反显 |
| `full/contest_full.cst` | 新增A20/B20两路3.3V约束 |
| `full/contest_full.sdc` | 只增加OLED外部返回到第一级同步器的异步例外，级间与其他逻辑继续计时 |
| `rtl/instrument_full_system.v` | 本地菜单直接读取独立TRANSPORT状态，截断上传完整性归约回到菜单的长路径 |
| `rtl/performance/performance_controller.v` | 内置曲谱与上传曲谱一样使用一拍行缓存、索引匹配后消费 |
| `rtl/sensors/mpr121_key_eventizer.v` | 无效拍保留旧数据，由valid决定消费，避免valid穿过source译码/屏蔽后再控制FIFO |
| `sim/tb_oled_board_integration.sv` | 完整顶层、原厂PLL、引脚解码、菜单快照、无屏/掉线恢复与音频隔离 |
| `sim/tb_oled_timing_regression.sv` | 内置32条事件的顺序、反压稳定、释放及独立状态检查 |
| `scripts/verify-oled-integration.py` | 从引脚捕获的1024字节做独立字模核对及生成预览PNG |
| `scripts/verify-oled-integration.ps1` | 隔离仿真与可选Gowin构建 |

OLED不接音频ready链、不控制音源复位；缺屏只让本地oled_fault置位、限速重试，不应停止弹奏。没有新增PLL或把I²C SCL作为片内时钟。主工程的event/cmd/done/sample接口保持原样。

## 验证与实物测试

实际测试与时序结果见交付的“验证结果.md”，没有结果不能仅凭生成文件宣称通过。默认100kHz专项检查在完整顶层原厂PLL仿真中测SCL低/高脉宽；快速功能回归仅加速显示和菜单等待，不代表实际刷新速度。仿真不会模拟屏幕发光或杜邦线电气质量。

可在项目根目录（或交付包的 `fpga-source` 内）复现。需要Python 3.11及以上、ModelSim和Gowin；路径不同时传入对应参数。默认只做20项仿真、引脚映射核对和显示字节核对，追加 `-Build` 才执行隔离综合布局布线：

```powershell
.\scripts\verify-oled-integration.ps1 -Python "C:/你的Python路径/python.exe" `
    -ModelSimBin "C:/modelsim/modeltech64_10.6e/win64"

.\scripts\verify-oled-integration.ps1 -Python "C:/你的Python路径/python.exe" `
    -ModelSimBin "C:/modelsim/modeltech64_10.6e/win64" `
    -Gowin "C:/Gowin/Gowin_V1.9.12_x64/IDE/bin/gw_sh.exe" -Build
```

脚本自动复制到英文临时目录，结束时输出验证现场和输入清单位置。两条命令都不会扫描下载器、下载板卡、覆盖旧位流或推送仓库。

下载新位流后先看启动音色页面；再长按滑条检查总菜单与反显，切换音色/音区、录制和回放核对画面。显示断线时声音应继续；重新接线须先断电，重新下载SRAM程序后再检查。真实OLED亮屏、方向、地址、亮度和长期稳定性均待现场验收。

若下载成功仍黑屏，先核对：是否用了本版 `.fs`、VCC是否来自3.3V、四根线是否按屏幕丝印连接、J13脚号方向是否正确。之后再确认卖家给出的控制器和7位地址；0x3D需要改顶层参数并重新构建。不能靠增加音量或改音频时钟修复OLED黑屏。交付的GUI工程保留 `full/rtl` 下与源文件同哈希的ROM副本，整个 `fpga-source` 一起保存，不要只拿走 `.gprj`。

旧LearningMode位流及Windows软件保留。本次不自动下载，不尝试推送无写权限的GitHub仓库。
