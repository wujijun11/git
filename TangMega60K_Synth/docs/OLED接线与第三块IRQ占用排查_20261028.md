# OLED接线：第三块MPR121的IRQ占用了A20

日期：2026-10-28。状态：用户已澄清接线，修正接线后的实物结果待确认。本次只记录与指导接线，没有修改RTL、约束或位流，没有自动下载或推送。

## 用户反馈与核对

用户最初报告A20接到第三块触摸模块的CL，随后明确更正：实际接到第三块的IRQ。用户反馈琴键可以发声，但尚未单独记录第17～25键的完整检查，也没有确认OLED已经亮屏。

已核对已发布版本`b238c4a`的`full/contest_full.cst`与OLED波形版真实构建引脚表`docs/reports/oled-idle-wave-20261027/selected-r2/ContestFull.pin.html`：

| 功能 | FPGA球位／应核对的丝印 |
|---|---|
| 第三块MPR121的CL/SCL | B13 |
| 第三块MPR121的SDA | C13 |
| 第三块MPR121的IRQ | A16 |
| OLED的SCK/SCL | A20 |
| OLED的SDA | B20 |

OLED VCC使用底板外设接口明确标注的3V3；GND接公共地。可从PMOD1的3V3/GND取电，已占用电源脚需可靠分线。A20/B20不能与AA20/AB20混淆。现场丝印、插孔和当前下载文件仍应实物核对，不能把源码检查当作导通测量。

## 为什么IRQ接错也可能发声

### 引脚历史复核

针对用户询问“是否之前一直接错”，实际检查Git历史：第三块`mpr_irq_n[2]`的A16约束来自2026-10-11的`fed89d5`，此后未被修改；队长仓库旧版本`d5b4ae5`、学习版`7f1b483`与当前发布版`b238c4a`均为A16。2026-10-26的`4bee4c9`才新增OLED SCL→A20、SDA→B20，没有迁移第三块IRQ。选用OLED波形位流的实际引脚报告也确认第三块IRQ在A16。

因此，若现场这根IRQ线确实一直插在A20，则它与上述已核对版本的分配一直不符；不能据此证明用户过去每次运行的位流或全部物理接线。此前发声反馈仍有效，不能因这次发现把所有历史故障都归到该IRQ上。

`rtl/sensors/mpr121_sampler.v`在初始化完成后，等待周期到达或IRQ拉低都会发起状态读取：`timer >= POLL_CYCLES-1 || !irq_n`。因此正常IRQ不是唯一读取触发条件，周期轮询可能维持按键工作。琴键能发声不能证明IRQ线已接对。

当前工程为OLED和MPR121分配独立总线。不能把触摸IRQ与OLED时钟共接A20；MPR121可能拉低IRQ，干扰OLED时钟。尚无实屏结果，不能宣称这就是已观察到的OLED黑屏根因，更不能据此解释此前FPGA蓝灯。

## 建议修正与验证

1. 关闭功放并断开整套相关供电，包括FPGA专用电源与DEBUG USB；独立供电的外设也先断电。
2. 确认A16没有其他线路占用，将第三块IRQ对应的FPGA端从A20移至A16；其CL/SCL、SDA先保持不动。
3. OLED接为SCK→A20、SDA→B20、VCC→3V3、GND→公共GND。
4. 上电后重新下载现有`ContestFull_OLEDIdleWave_TEST1024.fs`到SRAM，核对Finished及UserCode`10C2`；断电会清除SRAM中的临时程序。
5. 单独检查第17～25键，再检查OLED文字、滑条菜单与空闲波形。记录是否恢复，不提前填写通过。
