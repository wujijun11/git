# GAO板内数字验证（2026-09-23）

## 工程与运行方式

新增独立入口 `BoardAudioGAO.gprj`，顶层为 `rtl/board/board_audio_gao_top.v`，复用现有 `live64_system_top`。原主音源与手动板级诊断入口未被替换。

上电后自动执行：复位 → 启动64声部 → 保持约1秒 → 停止 → 等待释放完成且声部数归零 → 完成次数加一 → 下一轮。错误、任意非零欠载及等待超时会置位粘滞 `fault` 并停机。每轮音源复位会清除其欠载计数，但不会清除该粘滞故障。

配置 `debug/board_audio.rao` 用系统时钟采集4096点，观察状态、声部数、欠载及内部I2S。此工程不输出外部DAC引脚，不能用于模拟音频验收。

## 验证边界与下一步

本次完成板内满声部运行、自动释放重启及I2S数字格式检查，未逐样本对比实物PCM的算法期望值，未验证外置DAC、模拟音质、准确音高或演奏端到端延迟。音高参数目前按48kHz生成，需与实际音频时钟统一。完整262144帧ModelSim频谱回归另行运行，不能用此GAO检查替代。

继续调试时在GOWIN打开本工程，进入Gowin Analyzer Oscilloscope，加载对应RAO与匹配码流，按F1采集；查看 `fault`、`active_count`、`completed_runs` 和I2S信号。DAC到货后再核对物理引脚、电平与供电并开展外部输出验证。
