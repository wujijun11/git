# PR1014 时钟布线调查（2026-09-22）

结论：现有V22硬件接线下尚未消除PR1014。主工程保持实际板载50MHz输入，未屏蔽警告、未改成无时钟连接的引脚，也未使用不适合作为精确音频参考的内部RC振荡器。

## 证据

- NEO Dock 31004 Rev1.4原理图第18页：核心板50MHz晶振接V22（EMCCLK）；MS5351 CLK2接AB12，BANK9要求LVCMOS15。
- GOWIN目标器件报告：V22为IOB117[B]/EMCCLK；AB12为IOB18[A]，均未列为GCLK输入。MS5351 CLK2可编程，不能仅凭晶体25MHz就推断CLK2实际输出25MHz。
- 高云SUG937E对PR1014的解释是时钟布线包含通用布线，并建议核对时钟来源和专用时钟端口位置：<https://cdn.gowinsemi.com.cn/SUG937E.pdf>，印刷页93。

## 编译试验

| 方案 | 结果 |
|---|---|
| 原V22直接输入 | PR1014，50MHz时序通过 |
| V22指定BUFG或BUFG[0] | PR1014仍存在 |
| V22→PLLA，50MHz→50MHz | 输入sys_clk_d仍有PR1014 |
| V22→DCE（CE固定为1，依据UG306的全局时钟使能原语） | 输入sys_clk_d仍有PR1014；已撤回 |
| PLL参考输入强制LOCAL_CLOCK、输出强制BUFG | 新增CT1018，并仍有PR1014；已撤回 |
| 同一RTL仅将时钟CST改到K18/GCLKT_6作对照 | PR1014消失，Fmax95.912MHz，Setup/Hold违例均0 |

K18只是证明问题来源的编译对照，不是实物接线建议；尚未核对其底板占用、可访问性和外部信号冲突，禁止直接烧录该试验配置。最终工程已恢复V22，并重新构建覆盖试验位流。没有保留试验PLL。

进一步核对官方CST：K18当前映射为HSPI_HD[5]，不是空闲时钟接口。其他GCLK也映射到PHY_CLK、Joy-Con或HSPI信号，不能仅凭专用引脚名称就直接接线。DCE试验额外产生的board_clk时钟约束提示随试验RTL一起撤回，最终版本不包含DCE。

## 真正消除警告所需工作

需要先从实际板版本的原理图中选定可安全使用的专用GCLK输入，再将适合的外部时钟接入该引脚，核对电压、占用和信号完整性，最后修改CST并重新验证。也可以评估其他有文档支持的专用时钟通路，但不能仅凭PLL综合成功就认定输入布线已修复。

在不改变现有接线的条件下，目前只能保留明确的告警和通过的静态时序结果。静态时序通过并不代替实物稳定性或音频时钟精度验证。
