# 启动欠载修复

## 原因和改动

复位释放后，I2S在第16个系统时钟开始第一帧；音源仍需初始化声部RAM并计算首个样本。此前空FIFO会直接计一次欠载，因此板内记录出现启动值1。

`rtl/i2s_tx.v` 增加播放启动状态：首个有效左右声道样本对被取出或在帧边界直通后，才启用欠载检测。在此之前连续输出成对静音，BCLK/LRCLK和frame_tick持续运行。正常播放后缺帧仍输出静音并置位脉冲、粘滞标志及累加计数；补供不会清除历史故障，只有复位清除。

此状态以有效握手的数据为准，首个全零静音样本也会启动监测。一直未提供第一帧的数据源不会触发播放欠载，需要上层用启动超时识别；GAO自动诊断已有超时检查。

两个板级诊断顶层均取消允许一次欠载的例外，任意非零欠载即故障。GAO CSV检查脚本默认要求零欠载；复核修复前的历史CSV时才显式传 `--max-underruns 1`。历史波形没有修改，不代表修复后上板结果。
