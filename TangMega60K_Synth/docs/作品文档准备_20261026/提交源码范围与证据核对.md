## 3. 赛题要求与现有功能的对应

| 赛题项 | 代码/设计对应 | 提交前还需什么证据 |
|---|---|---|
| ≥2个独立动作采集维度 | 实体键选择/触发＋四电极滑条连续音量；菜单功能保留 | 当前版本实物同时操作、传感稳定性和控制独立性 |
| 全HDL实时音频 | DDS/八成分/FM、ADSR、混音、FX、I2S均为可综合HDL | 标明主通路与ROM内容；真实板上输出，不能用电脑本地试听冒充 |
| ≥4复音、拓展≥32复音 | 64逻辑声部分配与音源，独立状态、尾音回收 | 在提交版本实际运行目标负载，并有可闻/谱峰证据 |
| 多维表情 | 增益、弯音、颤音深度及力度运算；帧快照和平滑 | 展示每个参数分别生效；软件参数数目不自动等于独立实体传感维度 |
| ≥2种音色 | 正弦、风琴、八成分钢琴、FM可切换 | 同音高/力度/音量对比，说明乐器音色选择 |
| 硬件音效 | 运行时延迟、混响、合唱及旁路 | 干湿切换、尾音和稳定反馈实测 |
| ≤10ms/拓展≤5ms | 有数字接口仿真与预算分析 | 当前完整实物总延迟；定义起止、阈值、重复次数和最大值 |
| 视听反馈 | HDMI波形/XY/64频点、OLED菜单、25灯 | 显示不阻塞音频、实际灯序/屏幕与音乐同步情况 |
| 脱机曲谱指引 | 板上RAM曲谱、定时LED指引与等待弹对学习 | 上传后断开客户端仍可运行；灯键编号正确；不能断电丢RAM后宣称永久存储 |
| BLE智能联动 | Windows/Android控制、曲库/MIDI、上传、事件录音读回 | 对应版本客户端/C3重建记录与真实连接、断连释放测试 |
| 现场振荡器验证 | 已有live64事件源、正弦PCM采集、FFT脚本 | 固定当前可用诊断入口、64理论频率及DAC实测频谱，不能只放旧图 |

八成分钢琴每声部8分量，不能仅用“64×8=512”宣布512个评分振荡器同时可闻：分量可能衰减/被带限抑制，独立控制及现场可观测性也需按规则证明。稳妥主线是先证明64个独立声部、64个正弦频率和实际48kHz；对应吞吐量为64×48000=3072000个振荡器样本/秒，现场是否成立由实际验证决定。

## 4. 源码提交包建议

建议参赛最终包从一个冻结提交导出，而不是把开发目录整个拖进去。目录可保持原项目结构，减少路径修改风险：

```text
submission/
  README.md                 版本、工具、主入口、快速复现
  source/TangMega60K_Synth/  保留原相对路径
    full/ rtl/              FPGA主工程、约束、全部列入的RTL与ROM
    desktop/ mobile/        上位机和原生宿主、配置与依赖
    firmware/               C3固件及带许可的本地BLE库
    hardware/               原生CAD、BOM、几何定义与必要工具
    scripts/ sim/           复现入口、测试台和冻结参考
    assets/ licenses/       音色参数、字体、授权与来源
    examples/               有用的独立接入示例
  evidence/                 对应冻结版本的精选日志、STA、频谱与测量
  binaries/                 可选的fs、Windows包、APK、C3固件及哈希
  documents/                技术报告、使用说明、演示脚本
  manifest.json             源码提交、输入哈希、工具版本和验证状态
```

当前复现脚本可能引用旧独立工程/文档路径，正式精简时先核对依赖；首次提交准备可以保留这些小工程作为`legacy-tests`说明，不能删完后不跑复现检查。现有自动交付器只覆盖各自版本，不等于已经生成上述最终参赛包。

不要打包：`.git`内部数据库、IDE缓存、Python虚拟环境、`node_modules`、Android SDK/JDK/Gradle缓存、ModelSim工作库、大量重复WLF/实现目录、账户信息/令牌/配对记录、与作品无关的截图和个人文件。保留少量有意义的原始波形与对应检查脚本即可；二进制产物按官方容量限制决定。

提交前在新路径解压，从README入口实际构建/仿真一次。源码和.fs同时提交可以，但必须记录.fs由哪个源码、GPRJ配置和工具产生，防止旧位流和新源码放在一起。

## 5. 必须保留的第三方来源

- `firmware/libraries/BridgeBLE/`：上游Espressif Arduino 3.3.5的BLE库、Apache许可、`UPSTREAM.md`和源码清单。仅`BLECharacteristic.cpp/.h`包含本地修正；重建C3要使用此库，不能悄悄换回系统同名库。
- `rtl/clock/pll_init.v`及高云原语：厂商IP/工具依赖，与自研RTL区分。仿真库通常由接收者安装工具后生成，不把完整商业工具安装包塞入源码。
- `licenses/menu-font/`：Unifont字模来源和OFL许可，保留必要署名。
- `assets/audio/README.md`与`LICENSE-Salamander.txt`：Salamander Grand Piano v3 / Alexander Holm / CC BY 3.0参考来源；当前参考单音用于离线数学拟合，未把整段原PCM装入FPGA。
- 公开曲库和用户导入MIDI：保留每首来源/许可，不因“不商用”就删去来源。演示音乐选授权清楚的曲目或自写旋律。

## 6. 提交前按这个顺序收尾

1. 选定唯一正式功能版本，完成当前滑条、OLED、灯序、学习和持续演奏的实物验收。
2. 复现对应64音频谱；完成真实动作到DAC/声学输出的延迟测量，并明确两者差别。
3. 核对软件与C3产物确由相应源码生成，单独测试BLE快速弹奏、断连释放、后台播放。失焦不主动停止不等于Windows所有后台状态都保证定时精度。
4. 固定构建快照、引脚、时钟和GAO开关，记录最终STA、警告、资源、源码和二进制哈希。
5. 按官方模板生成最终技术报告/视频/源码包，再从新目录复验。此时才决定是否合并或发布。
