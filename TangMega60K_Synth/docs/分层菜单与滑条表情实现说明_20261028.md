# 分层菜单、滑条表情与OLED波形测试版

日期：2026-10-28。本地测试分支：`codex/menu-confirm-wave-20261028`。

本轮按用户确认的四类菜单实施，保留上次`ContestFull_OLEDIdle10s_TEST1024.fs`。没有自动连接、扫描或下载板卡，没有推送远端。当前核心板熄灯/间歇性启动异常仍未定位，本次菜单工作不作为故障修复。

## 操作规则

默认处于连续音量控制。最左端长按约1秒后松手打开总菜单；菜单内短触一个区域、松手后执行。右端长按从菜单回音量，第四区的预览高亮仍保留，不能把高亮当作动作已执行。

| 总菜单区域 | 进入后的四项 | 后续 |
|---|---|---|
| 声音 | 音色、音区、音效、返回 | 音色/音区/音效各有四项，返回进入总菜单 |
| 表情 | 音量、弯音、颤音、复位 | 进入对应连续控制；复位清弯音/颤音并回音量 |
| 录放 | 开始、结束、回放、停止 | 复用原录制/停止录制/录音回放/PANIC动作 |
| 曲谱 | 播放、停止、指引、学习 | 复用原曲谱播放/停止/定时指引/等待按键学习 |

声音的子项：

| 页面 | 第一区 | 第二区 | 第三区 | 第四区 |
|---|---|---|---|---|
| 音色 | 钢琴 | 风琴 | 正弦 | FM |
| 音区 | -24半音 | -12半音 | 不移调 | +12半音 |
| 音效 | 关闭 | 延迟 | 混响 | 合唱 |

音色与音效均使用已有算法，不新增钢琴采样播放或改变八成分合成。进入“声音”或“音色”等页面时不会立刻退出；实际设置/动作成功后才显示波形。失败时保留文字错误提示，不伪装成功。录放/曲谱的停止、重试及先停止旧任务的处理仍经原动作路由器。

菜单闲置10秒显示波形，再触摸回音量。普通设置成功后也是波形，下一次触摸调音量。表情选择是例外：选择弯音/颤音后直接显示该控制，闲置10秒显示波形，再触摸恢复该表情。唤醒的整次触摸用于连续调节，左端长触也不会同一次又打开总菜单；需要松手后再次左长按打开菜单。

## 百分比、音分与音量保留

| 表情 | 滑条范围 | OLED数值 | 松手行为 |
|---|---|---|---|
| 音量 | 0..3072映射Q1.11 0..2048 | 0..100% | 保持 |
| 弯音 | 左-200、中心0、右+200音分 | 带正负号的音分值 | 归零；传感器故障/退出模式也归零 |
| 颤音 | 0..100音分深度 | 0..100%深度，100%=100音分 | 保持 |
| 复位 | 只提交bend/vibrato掩码 | 回音量视图 | 音量保持，不强制变成100% |

切换控制类型不把原音量百分比当作另一个参数的初始值。显示值来自V2采样帧提交后的实际参数，不只显示手指位置；原音源仍对目标进行逐帧平滑，因此这里的数值是已提交控制值，不是测得的喇叭瞬时频率。

音量映射保留原683/1024近似2/3的固定比例、端点限制与4个Q1.11单位的位置回差；只生成参数，不改变混音增益标度。弯音范围限制为正负2个半音，音源仍保留原V2的正负2400音分能力；电脑/手机弯音大于本地范围时，OLED显示实际音分，刻度限制在两端。颤音沿用现有全局LFO及深度平滑，参数提交仍在`engine_sample_begin`边界完成。

真正的两音自动滑音(portamento)本轮没有新增；滑动弯音与音源的参数平滑不计作已实现独立滑音功能。

触摸数字快照经过手势模块进入导航，再向已有动作路由器提交请求。表情经过独立掩码控制模块进入`expression_merge`，与手机参数公平合并，再由`expression_controls_v2`在帧边界提交，音源实时计算声音。显示只观察参数、状态及实际I2S PCM，没有参与音源ready或局部复位条件。

菜单动作完成后在当前I2C页事务结束的边界更新屏幕，不中断已经开始的事务。100kHz总线传送整屏数据存在约百毫秒量级的传输时间，显示刷新不等同于音频响应时间；本轮没有承诺屏幕零延迟，也未实测屏幕刷新率。

新手势与导航独立于旧`slider_menu_controller`；`instrument_full_system`默认仍关闭`HIERARCHICAL_MENU_ENABLE`，便于复现旧入口。完整顶层默认开启`MENU_HIERARCHY_ENABLE`。二者由综合常量选择，未在一份位流中同时运行两套菜单。

新增字模是独立的`menu_hierarchy_font.hex`，99字、4096字节，授权在`licenses/menu-hierarchy-font/`。旧`menu_font.hex`和音频ROM不改动。GPRJ和构建脚本增加新源码、字模依赖，不改引脚、PLL或SDC。

## 验证与问题记录

首轮编译发现一处十六进制常量紧贴条件运算符导致的词法错误，已增加分隔并重新运行；失败日志保留，不计作通过。修正后的两项单元专项，以及包含真实音源、UART、MPR数字快照和生产顶层PLL/I2S/OLED的四项整合仿真已经实际通过。

最终36项相关ModelSim回归于2026-10-28 15:33:49完成，全部通过，RTL/ROM/测试台/运行器输入哈希保持一致。新整合测试实际完成190次数字快照、20次真实UART应答和470帧PCM输出，覆盖本地表情、录放、学习、音效、PANIC、传感器故障，并检查远端音效同值提交可以覆盖本地选择。编译包含端口省略等警告，不能写成零警告。

独立文字参考首次把“事件数”和四位数字之间的空格遗漏，导致参考比较失败。核对布局后只修正Python参考字符串，RTL和测试台未改变；对已采集12帧重新逐字节核对，12288字节全部一致。失败不能计作通过，修正原因保留在本说明。

由于新旧顶层测试共用波形导出文件名，完整回归后又独立复跑新生产顶层一次，单独封存I2S PCM与OLED像素，避免旧入口覆盖新证据。新顶层独立采集同样通过，真实输出PCM到768字节波形区的独立参考比较另有日志和预览；这不是外部DAC实测，也不代表测得触摸到喇叭延迟。

新顶层独立采集的512个PCM样本SHA256为`207F1DF49693BD1ABDEA87C9D93C59425121C840C1EEF787C533521F41078F55`，与旧10秒版相同测试情境的样本一致；该结论仅覆盖这段采样，不推广为所有演奏输入都已比较。768字节波形区参考比较通过，帧哈希为`A39E18C541156CA9392A32243A0DBDB9654ECC0D4F7D3A9F27C321FB0C48EDAC`。音频RTL、音频ROM、PLL相关源码、公共表情寄存器及CST/SDC共29个受保护文件逐文件核对未变。

## 复现

```powershell
./scripts/verify-menu-hierarchy.ps1 -Python 'C:/你的Python/python.exe' `
  -ModelSimBin 'C:/modelsim/modeltech64_10.6e/win64' -Build
```

字体可用同版本原字库重新生成：

```powershell
python ./scripts/generate-hierarchy-font.py ./unifont-16.0.04.hex.gz
```

字体生成器会校验原文件SHA256，不能随意换用授权与位图不一致的字体。下载须由用户在供电稳定后手动执行；测试包使用独立名字，保留原10秒版回退文件。
