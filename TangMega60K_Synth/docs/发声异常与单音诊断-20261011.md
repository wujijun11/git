# 发声异常与单音诊断（2026-10-11）

下文保留早期发声异常与独立诊断记录。后续自动诊断已由用户报告音高变化及控制正常，完整主工程随后通过Gowin Programmer GUI恢复，最新用户码为 `0x0000F0A6`。主工程复测的KEY0播放/停止/重播、KEY2复位恢复、KEY1停止及退出后重播均由用户报告通过；声音有音高变化但仍偏轻，音质和旋律尚未验收。最新结果见[主工程板上复测](hardware/主工程板上复测-20261011.md)。

## 录音与软件检查

对 12.01 秒手机视频在本地提取原始立体声音轨，分别以 250ms Hann 窗作 FFT。约 0.5–7 秒的主要窄带成分位于 2.65kHz 附近，在 250–4500Hz 带内功率占比中位数分别约为左 88%、右 83%。未识别到预期的连续变化旋律。这个结果是麦克风录音分析，不是 DAC 电气测量，也不能单独判定接线、供电或 DAC 模块有故障。

使用真实 RTL 音源路径逐键测试，25 个 MIDI 音符、50 次音符事件、25 次释放通过。C4/D4/E4/F4/G4 的频谱随音符变化，数字音源没有固定在 2.65kHz。默认钢琴单音峰值约为 −62～−64dBFS；这个电平来自固定 64 声部同相叠加、最大表达增益的预留余量。`MASTER_SHIFT=1` 没有另除以 64，不能把它解释为 I2S 位宽错误。

录音分析及原始 RTL 数值记录见 [video-analysis.json](../verification/audio-diagnostic-20261011/video-analysis.json) 与 [cdefg-reference.json](../verification/audio-diagnostic-20261011/cdefg-reference.json)。私人视频和提取音轨保留在工作区临时目录，不进入源码仓库或发布包。

## 独立诊断方案

诊断只保留一个声部，使用相同音源、参数 ROM、49.152MHz PLL 和 24 位 Philips I2S。`MASTER_SHIFT=7` 比原混音尺度提高 36.1dB；单声部 16 位满幅、最大表达增益仍可放入 24 位输出。主工程的 64 声部混音尺度保持原样，不能把这个诊断增益直接套用到 64 路叠加。

测试顺序为五个正弦音 E4、F4、G4、D4、C4，再停顿，然后播放钢琴音色的 16 音《欢乐颂》简化片段。每个音符释放完成后才开始下一音，防止旧音尾音叠加。

下载前已请用户把功放音量调到刚开机后的最低位置；用户已确认完成，DAC 接线保留、J13 空置。诊断默认静音，需按 KEY0 开始。KEY1 停止，KEY2 复位。

## 构建、仿真与下载记录

诊断工程已实际完成构建，建立时间余量为 7.258ns，保持时间余量为 0.004ns，建立/保持违例均为 0。使用 61/118 个块 RAM（52%）；这只是独立单声部工程的数据，比赛主工程仍为 106/118（90%），建立时间余量为 0.171ns。保持余量仍很紧，不能根据无违例报告代替实物稳定性测试。

完整仿真通过 21 音、194,657 个外部 I²S 帧、194,659 次逐样本增益对照；无削波、无欠载，并通过停止、重播、复位和长按不自动循环检查。频谱核对全部 21 音通过，前五个正弦音的拟合频率约为 329.627、349.228、391.995、293.665、261.626Hz。初轮末尾覆盖断言失败来自测试强制背压的计数少一个采样时钟；校正测试后完整重跑通过，已构建 RTL 未作更改。

诊断位流已通过 DEBUG USB 下载到 SRAM，进度 100%，随后读出器件 ID `0x0001481B`、用户码 `0x00006987`、状态码 `0x70026020`。这证明下载工具完成并能读取器件代码，不是整个配置内容的回读验证。下载记录见 [diagnostic-hardware.json](../verification/audio-diagnostic-20261011/diagnostic-hardware.json)，仿真见 [diagnostic-validation.json](../verification/audio-diagnostic-20261011/diagnostic-validation.json)。

本节下载发生后，板上曾运行单音诊断。完整功能位流保留在 `release/contest-full-optimized-20261011/ContestFull.fs`，之后已恢复完整主工程；诊断位流保存在 `release/mono-diagnostic-20261011/MonoDiagnostic.fs`。SRAM 配置断电后丢失。

首次诊断下载后，用户报告仍是固定尖音或杂音，随后报告 KEY0 没有反应；当时提高电平未证实解决异常。按用户要求重新下载同一诊断位流至 SRAM，进度 100%，器件代码读回一致。后续又使用自动诊断，用户报告音高变化且KEY0重播、KEY1停止、KEY2复位恢复正常；该反馈不等于精确音高或失真测量通过。

如果再次出现固定尖音或不响应，可先区分 KEY1 停止和 KEY2 复位后的噪声变化，再断电核对 WSEL/LCK→AB21、BCK→Y21。板背 PMOD1 丝印下排依次为 `3V3 / GND / AA19 / AA20 / AB21 / Y21`，从正面观察会镜像；以实物丝印和导通为准。DIN→AA20 的历史导通测量不能代替另外两条；本次复测未重新测量供电、FMT或SCK配置。

本文件的诊断方案不是整机验收结论。完整主工程已有用户听测的音高变化与控制反馈，旋律、失真和模拟输出电平仍待测量；25 键、滑条、BLE、外部指引灯及物理延迟测试仍等待相应硬件。
