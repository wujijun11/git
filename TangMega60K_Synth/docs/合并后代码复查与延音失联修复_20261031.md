# 合并后代码复查与延音失联修复

日期：2026-10-31，检查基线`63d461d`。对主工程、延音门控、声部分配、UART、
看门狗及电脑/手机接口逐项复查，确认并修复以下两处逻辑问题。

## 1 全部松键后远程延音没有失联释放

旧看门狗只在存在远程按住的琴键时计时。远程开启延音后松开全部琴键，
音源仍保留声部，但看门狗的held集合已为空；此时突然失联不会触发原清音流程。
旧代码在新的全系统回归中报错`remote sustain survived lost heartbeat with all keys released`。

修复在主集成层记录延音设置的最近写入来源，并通过内部keepalive_required信号复用原看门狗计时器，
没有增加第二套心跳计时器。远程拥有的延音在连续3秒没有已接收UART命令后进入释放流程，
通过原延音门控补发已松键声部的释放，不用全局音频复位。
本地独立开启的延音不进入新增远程计时；本地/远程接管保持原先的写入优先级。
持续心跳保持远程延音，PANIC与音频复位仍清除状态。原有按住远程键的断连保护保持。

## 2 力度0事件的按键占用语义不一致

声部分配器原本将NOTE ON且velocity=0视为NOTE OFF，但看门狗仍按NOTE ON记录。
这会留下并未实际按住的远程键，随后可能错误触发失联清音。
新增回归复现了`velocity-zero NOTE ON armed held-key watchdog`。
修复让看门狗也使用`remote_on && remote_velocity!=0`，与已有V2分配器语义一致。
