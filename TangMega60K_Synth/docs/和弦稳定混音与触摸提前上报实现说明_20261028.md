# 和弦稳定混音与触摸提前上报实现说明

日期：2026-10-28。本地独立测试分支：`codex/chord-gain-stable-20261028`，基于`e44f5ff`。本轮只处理用户确认的和弦音量与触摸延迟，不改钢琴八成分音色配方、包络、频率表、PLL、引脚或公共V2端口。没有下载板卡，没有推送或合并远端。

## 1. 问题与目标

旧音源根据每帧活跃声部数设置混音倍数：1声部64倍，2声部32倍，3～4声部16倍，之后继续分档。活跃声部包含释放尾音。此前的增益平滑只能缓和变化过程，两个声部稳定后仍会将原声部缩小一半。因此“再按一个键，原来的音变小”有明确的软件原因，但不能把现场所有噼啪、断声、核心板熄灯都归因于它。

新版在音符、力度和表情不变时保持单个声部的混音比例；实际混合峰值过大时再压缩保护。不能同时承诺无限叠加、保持所有音量以及完全无失真，有限输出范围必须作取舍。

旧触摸路径在收到完整43字节后才把按键状态交给事件转换器。新版收到前两字节触摸位图后立即发布，剩余41字节继续读取，供滑条、完整快照与诊断使用。

## 3. 固定标度与峰值保护

数据路径为：

`独立声部与包络 → 32位混音 → 固定左移6位 → 原Q1.11总增益 → 保留45位结果 → 立体声联动限幅 → 原音效 → 原I2S`

64路16位有符号样本求和至少22位；再左移6位仍在32位范围内。总增益乘法保留45位结果，限幅之前不截成24位，因此不会先发生数值回绕或先丢失削波信息。

限幅器使用左右绝对值的较大者确定同一个增益，避免左右声像因分别压缩而偏移。默认阈值为4,194,303，约为24位满幅的-6.02dB，给后级音效预留余量。阈值以内且保护增益已经恢复到1时逐位直通。固定64倍保持原单音标度，不对每个音或试听文件分别归一化。

超过阈值时计算：

`目标增益 = floor(阈值 / 当前峰值 × 65536)`

使用16次移位比较减法生成Q16比例，不使用除法IP、不增加时钟。当前帧立即降低增益，之后每个实际接收的样本最多增加64/65536，最多1024帧、约21.33ms恢复到1。左右相乘后舍入并钳位，不能截断回绕。反压期间不推进处理或重复接收；保持输出valid与左右样本稳定。

大乘法数据寄存器由状态有效性屏蔽，没有添加大范围异步复位。旧自动分档与平滑模块仍在源码中，关闭新参数即可切回旧实现；不能把旧实现的测试通过等同于新实现已经验证。

这是峰值保护器，并非物理建模或钢琴音色重做。实际过载会降低整组和弦的增益，可能产生压缩感或非线性成分；过载后短暂恢复过程中也可能影响较轻的音。此轮没有宣称解决所有噼啪声。主混音之后的延迟/混响/合唱沿用原算法，仍有原饱和保护；不能据此声称任意反馈条件下完全不削波。

## 4. 按键快通道与完整快照

1. 上电仍执行原初始化、配置读回与校准，`ready=0`时不发布早到的按键。
2. 正常轮询仍发出从0x00开始的43字节读事务；收到第0、1字节，组合12位触摸状态。低字节已经寄存，高字节随后到达。
3. 将状态存入单槽邮箱并置valid，由原事件转换器产生按下/松开，再经事件仲裁与声部分配器进入音源。
4. 同一个读事务继续执行，完整快照仍可驱动滑条；完整快照不再次馈入键事件，避免先新后旧或重复事件。
5. 邮箱未被接收时禁止下一轮正常读事务覆盖它。已呈现的状态在反压时稳定，松键在后续实际读取后有序交付。
6. 复位或明确故障撤销采集通道，同时撤销未确认的旧邮箱；原故障释放逻辑负责已经发出的键。故障取消是valid稳定规则的明确例外，不把旧键留到故障恢复后重放。
7. 高字节OVCF一旦已知就停止发键并触发原故障逻辑，完整事务仍由I2C主机自然结束，随后锁定至系统复位。若尾部超时，沿用原重试与故障策略。

**本实现不是把43字节改成2字节事务。** 它减少本次已采到按键的发布等待，不减少完整总线占用，也不提高整体滑条刷新率；刚好错过当前寄存器读取的变化仍可能等待下一次扫描。短于整个采样间隔、从未被MPR寄存器采到的动作不可能凭本修改恢复。

不提高400kHz，不修改触摸阈值、MPR滤波、校准次数或轮询周期。NXP资料中的触摸状态是0x00/0x01，I2C Fast-mode上限400kHz：[MPR121数据手册](https://www.nxp.com/docs/en/data-sheet/MPR121.pdf)。

## 7. 过程中遇到的问题

- 早期限幅单元测试使用超32位无尺寸十进制常数，ModelSim编译拒绝；改成显式64位有符号常数。属于测试台表达式错误，未冒充RTL测试通过。
- 早期按键邮箱测试把事务超时设为1000周期，短于整个43字节串行读取，导致初始化无法完成；恢复为足够的10000周期，再执行真实串行测试。没有为通过测试缩短生产读事务。
- 新增钢琴回归最初同时打开测试台的FM和POLAR开关，测试台优先运行FM分支，虽FM完成却缺少预期POLAR结束标记，判为失败；改为明确选择POLAR分支后重跑。旧失败日志单独保留，不能用FM结果代替钢琴验证。
- 邮箱单元日志默认按ps显示，却带了ns后缀；只增加一行`$timeformat`修正显示并单独复跑。封存脚本验证除了这一行外测试台字节一致，保留前后证据。正式延迟数字来自完整板级CSV，不使用该加速单元测试的时间差。
- 限幅耗时随峰值是否过载而变化，因此表情偏离中性后不应强求与中性参考输出在同一拍出现。中性阶段仍逐拍对比；本机反压、帧预算、LFO与快照检查始终保留。
