# 团队协作说明

## 当前交付范围

平台：Sipeed Tang Mega 60K。当前交付新增V2：64声部按来源管理、三维全局表情参数通道、24位立体声I2S及样本缓冲。原V1继续可用；迁移按[接口V2与队员迁移](接口V2与队员迁移.md)进行。
尚未包含振荡器、ADSR、混音、传感器驱动和可直接烧录的板级工程；64 声部最终混为左右两个音频输出声道。

| 目录 | 内容 | 对接建议 |
| --- | --- | --- |
| `rtl/` | 可综合的 Verilog 模块 | 队长维护控制器、I2S 和集成顶层 |
| `sim/` | SystemVerilog 测试台、ModelSim 脚本 | 所有成员提交模块时附相应测试 |
| `scripts/` | 本机测试、GOWIN 综合入口 | 工具路径根据本机安装位置指定 |
| `docs/` | 接口、使用说明、验证记录 | 修改接口时同步更新 |

## 两位队员如何接入

- 音频负责人：实现逐样本合成引擎。输入控制命令及尾音回收接口遵循《接口与第一课》；向队长输出 `sample_left`、`sample_right`（24 位有符号数）和 `sample_valid`，接收 `sample_ready`。
- 交互负责人：把选音、触发、松键与力度转换成控制事件，遵循ready/valid握手；V2新增source并保存松键所需的原音符列表，使用独立表情快照通道。
- 音频负责人迁移：原cmd/done/sample字段保持不变；V2新增engine_sample_begin与active参数连接。负责实现真实幅度平滑、弯音换算、颤音LFO，不能仅连端口就声明三种表情完成。
- 队长：维护接口协议和集成顶层，负责控制器、I2S、联合仿真及后续板级时钟、引脚和时序验证。

所有 ready/valid 接口都只在两者同时为 1 的时钟沿完成传输。valid 为 1 而 ready 为 0 时，发送方必须保持 valid 和负载稳定。
当前音频入口与 I2S 发送器使用同一系统时钟；跨时钟模块不得直接接入，应先设计并验证跨时钟传输。

## 获取和运行

```powershell
git clone https://github.com/wujijun11/git.git
cd git/TangMega60K_Synth
./scripts/test.ps1 -ModelSimBin 'D:/msim/modelsim_ase/win32aloem'
```

若安装在其他位置，替换 `-ModelSimBin`。脚本同时检查控制器与 I2S 测试的退出码和通过标志。
GOWIN 打开 `TangMega60K_Synth.gprj`；仿真操作见 README 和第二阶段说明。

## 提交与合并

1. 队长为队友配置仓库协作者后，队友克隆仓库；也可使用个人 fork 提交 Pull Request。
2. 从最新 main 建立自己的功能分支，例如 `feature/audio-engine` 或 `feature/input-events`。
3. 每次提交仅包含相关源文件、测试和说明；使用 `git add <具体文件>`，先查看 `git diff --staged`。
4. 推送个人分支，在 GitHub 创建 Pull Request，说明功能、接口变化、测试结果和未完成事项。
5. 队长审查并运行联合测试后合并。发生接口冲突时先协商，不直接覆盖其他成员文件。

上传前不要包含安装包、许可证、账号凭据、仿真 work 库、波形数据库、工具缓存及个人路径配置。
这些文件仍可保留在各自电脑；项目的 `.gitignore` 会排除常见生成物。
