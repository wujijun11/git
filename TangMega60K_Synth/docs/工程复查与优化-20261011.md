| 问题 | 修改 | 验证 |

| 全字段表达请求可能覆盖实体滑条弯音 | 只发送被拖动维度的mask，多维待发变化合并 | 仅调增益的mask=1；增益和颤音合并mask=5，均不写弯音 |

| 窗口失焦时手机持键可能未释放 | blur与隐藏页面触发手机持键释放，取消待发表达 | 持键失焦后遥测为0、held集合清空；断线后旧表达不进入新会话 |
| GOWIN切换工作目录后相对报告路径误报缺失 | 构建路径在启动时固定到脚本所在工程，保留Windows路径拼写；时序检查继续强制执行 | 必须以最终构建日志中的TIMING PASS及STA报告为准，不能只看生成了.fs |
| BLE写入Promise一直不返回，后续松键命令被永久阻塞 | 增加独立4秒写入期限；超时关闭会话，拒绝所有待发命令，不与悬挂写入并发重试 | 未收到ACK和已提前收到ACK两种悬挂写入均复现旧故障；修复后只写一次、只报一次失败，迟到完成不能启动下一条命令 |
| 调用者修改排队参数会改变实际发送内容；非法请求能卡住队列 | 入队前复制参数并验证，不消耗非法请求的序号 | 排队音符60在外部被改为72仍发送60；非法字节/操作码拒绝后后续合法命令按序完成 |
| 解码回调抛错被误当CRC错误，丢弃下一帧的同步字节 | 将帧校验与消费者回调分开，应用异常正常抛出 | 注入消费者异常后下一完整帧仍可处理，CRC错误计数不增加 |
| 同一曲谱键连续NoteOn，中途改映射后旧音没有释放 | 音高变化先释放旧音再发新音；同音重触发复用原声部；力度0规范为Off | 联合真实allocator验证60→61的Off顺序、满声部同音重触发、音色归属、力度0、背压、Stop/Panic和事件回放 |
| 浏览器旧设备的通知/断开回调可以影响新会话，已取消的连接晚返回仍会建立 | 回调绑定设备、写特征和解码器；连接代次检查并清理取消后的结果 | 假Web Bluetooth测试旧通知/断开、设备选择取消、服务发现取消和新连接隔离 |
| 手机两个键映射同音高，松开一指会停止另一指 | 手机source63同音高共享持键，最后一指离开才发Off；释放保存原音高并核对pointerId | 两指同音只发一次On；错误指针不能松键；重映射后最终Off仍指向原音 |
| Android已检查GATT归属的回调再次入UI队列，可能跨重连交付 | 在UI线程同一任务内派发JS；后台结果仍入队，已销毁WebView丢弃结果 | 编译实际MainActivity，确定性主机UI队列覆盖旧通知、旧写完成、后台派发及销毁；不代表实机Android蓝牙验收 |
| 64音测试首次Panic失败遗留运行标志；旧操作的ACK续执行改新会话UI | 初始请求纳入失败清理；映射/Panic/清记录提交前检查原会话 | 初始NACK和未连接都回到idle；旧ACK不能改新连接的map、held或recorded |
| 协议模拟记录开始保留旧事件、Panic不停止记录，与RTL行为不同 | 模拟开始清旧记录、Panic停记录、力度0释放、空事件回放拒绝 | 新增状态/记录数量/零力度/空回放回归；模拟仍不代替实物验收 |
