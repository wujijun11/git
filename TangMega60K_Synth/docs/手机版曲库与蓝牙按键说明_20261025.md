# 手机版曲库与电脑实时琴键

**版本修正**：当前Android1.4增加模式回传显示；电脑“跳过未发送短音”策略已撤销，下文相关描述为历史方案。新版本完整保留正常按下/松开，详见《模式同步与蓝牙延迟修正_20261025.md》。

## 已完成的使用流程

Android 1.3新增“找一首，弹起来”：输入曲名或作者 → 搜索Mutopia公开授权曲库 → 查看MIDI音轨 → 选择旋律/伴奏和起止秒数 → 分析事件数及25键音高 → 确认转换提示 → 导入当前曲谱 → 连接蓝牙并上传。

也可直接选择自己有权使用的 `.mid` / `.midi` 文件，无需联网搜索。Android文档选择器允许显示通用文件，因为不同厂商对MIDI的文件类型标注不一致；选中后仍根据MThd头和完整内容严格检查。曲库网络下载可以解包含MIDI的ZIP；手机本地文件选择暂只支持MID/MIDI，电脑版另支持本地ZIP。

手机和电脑都有1024条新版/256条旧版容量选择。应与实际下载的FPGA位流匹配，现有协议不能自动查询容量。完整MIDI保留在客户端；上传的是音符事件，不是PCM。断电后用户曲谱RAM会丢失，下次需重传。新曲谱替换现有用户曲谱，不是持续追加到无限曲库。

选“按片段音高重新安排25键”会在上传时发送25条映射命令，然后逐条写曲谱，最后提交。失败或主动取消时，只在同一仍连接的会话中尝试恢复旧键位。旧曲谱没有双缓冲保留保证；失败后应完整重传。录制期间拒绝上传。停止/断线能取消余下上传，不向重连会话补发旧操作。

## MIDI转换限制及来源

- 支持标准Type 0/1、拍数时间、速度变化、运行状态和零力度松键。
- 最多4MiB、128轨、20万消息；手机另限制24小时内的曲目，避免不合理时长。
- 片段开始补发已经按住的音；片段结束补松键，不留下悬挂音。
- 同音高重叠合并为一个键位，保留警告。打击乐通道会提示使用当前乐器音色。
- 踏板、弯音和触后等未支持的MIDI控制不导入；原MIDI乐器分配不自动替换当前FPGA音色。
- 超过事件容量或25种可映射音高会阻止导入，不截断后半首，不静默删除越界音。
- Mutopia不保证能找到流行歌曲；可导入有权使用的本地MIDI。网络曲谱来源、逐曲授权、下载地址和SHA256保存在曲谱元数据中，元数据不写入FPGA事件RAM。

MIDI是演奏指令文件，例如“第0毫秒按下C4、500毫秒松开”，不是录音。非商业用途也不自动获得复制、分享或公开传播的许可，应按每份文件授权使用并署名。授权说明：[Mutopia](https://www.mutopiaproject.org/legal.html)。标准MIDI格式参考：[MIDI Association](https://midi.org/standard-midi-files)。

## 代码如何分工

| 模块 | 职责 |
| --- | --- |
| `mobile/web/music/smf.js` | 读MIDI二进制、计算时间、选轨及片段、生成key事件，完全不接触BLE |
| `mobile/web/music/library.js` | 手机文件与解析数据管理、原生请求及回调，最多保留最近32个文件 |
| `mobile/web/music/panel.js` | 搜索结果、音轨、分析提示、确认和导入界面 |
| `mobile/web/app.js` | 既有演奏控制与上传调度、容量选择、失败恢复 |
| `mobile/web/protocol.js` | 固定16字节帧、CRC、ACK/重试和曲谱格式校验 |
| `mobile/android/.../MusicCatalog.java` | HTTPS站点限制、下载上限、缓存、ZIP和授权信息；独立工作线程运行 |
| `mobile/android/.../MainActivity.java` | Android蓝牙、权限、文件选择器与上述模块初始化 |

网络请求只允许Mutopia官方主机，重定向也检查；缓存有效期24小时，联网失败可读旧搜索缓存。ZIP只在内存解包，不按压缩包路径写文件，压缩和解压后数据均受4MiB限制，最多32个MIDI。下载内容不作为网页执行，原生权限页面只加载打包资源。

## 电脑琴键卡顿的改法

原程序逐条等待FPGA确认，快速点击可以积压很多已经松开的按下/松开，导致停止点击后还在慢慢补弹。

`desktop/web/controller.js`现在区分每一次真实按下：若它仍未开始发送，最后一个持有者松开时删除该过时请求；若已发出，则完整等待在途确认，再正常松键。不打断CRC帧或ACK/数据响应边界，不改变离线曲谱的完整事件上传，不修改C3帧格式或固件。

这能避免本机过时琴键积压，不能消除无线链路本身的往返时间。弱信号、连接间隔和桥接速度仍需实测。一次点击短于可用通信吞吐量且未发送，会被取消，保证实时控制不会在数秒后补弹；需要完整保留每个音符的曲目应上传后由FPGA本地定时回放。

要使用修复，应先断开并关闭旧Windows控制程序，再打开新交付文件夹中的 `TangNeonStudio.exe`。保留整个文件夹，不能只复制EXE。不要让两个客户端同时抢同一BLE连接。

1. 电脑控制器和10组队列测试通过；延迟确认下800次快速点击不补弹；同音高多持有者、重按、断线释放、全停及ACK/数据边界检查通过。
2. 手机9组转换与独立Python/mido参考逐事件一致，包括变速、选轨、边界补音、重叠、控制消息、重映射及1026条超限。格式错误、逐字节截断、Type 2/SMPTE/超大输入均拒绝。
3. 手机原协议、最小DOM控制流程及异步上传/断线回归通过。
4. 独立390像素无头浏览器：搜索桥使用固定数据激励；本地真实File导入、选择片段、确认、映射及1024条写入/提交通过，旧256容量在硬件写入前拒绝。它不是Android系统WebView/GATT测试。
5. Android曲库Java核心用真实Mutopia搜索HTML核对10条结果，URL限制、大小限制和工作线程错误回调通过。普通JVM测试注入标签解码，未冒充Android系统HTML解码实测。
6. Android 1.3 APK实际编译、lint通过，开发签名v1/v2校验通过。打包文件SHA256见交付清单。
