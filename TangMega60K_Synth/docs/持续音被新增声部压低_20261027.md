# 持续音被新增声部压低：自动混音增益策略问题

日期：2026-10-27。状态：原因已从代码定位，改进策略尚未实现；本轮未更改HDL、未重新构建或下载，保留已恢复基本功能的`ContestFull_HeadroomBootProbe_R2.fs`。

## 用户反馈与范围

用户在R2上反馈：一直按住一个琴键，再按其他琴键时，原有声音感觉减半。此前R2已由用户确认彩灯绿色、FPGA握手成功、实体琴键发声正常；这些基本功能仍成立，本次新增的是混音听感问题，不是此前无法握手/实体键失效的故障复发。

该反馈与现有RTL的自动增益规则一致。此前启动故障的根因仍未确认，不能把两件问题合并为同一已知原因。

## 实际代码路径与原因

完整系统仍启用`AUTO_HEADROOM=1`和`HEADROOM_SMOOTH=1`。`rtl/audio/voice_engine.v`统计每帧实际活跃声部（包含Release尾音），选择`frame_boost_shift`：

| 活跃声部数 | 目标倍数 | 代表性变化 |
|---|---:|---|
| 1 | 64 | 首音使用64倍 |
| 2 | 32 | 从1到2，已有声部的全局系数减半 |
| 3～4 | 16 | 从2到3再减半；从3到4不变 |
| 5～8 | 8 | 从4到5减半 |
| 9～16 | 4 | 从8到9减半 |
| 17～32 | 2 | 从16到17减半 |
| 33～64 | 1 | 从32到33减半 |

把原声部当前采样记为A，新声部记为B，只看这项增益：单音为`64*A`，双音目标为`32*(A+B)`。因此原声部A的系数从64变32，即使新声部B尚处于起音初期、振幅很小，A也已被压低。数字幅度减半约为-6.02dB，不表示人耳主观响度恰好减半，也不表示两音混合后的总幅度一定减半。

`rtl/audio/headroom_smoother.v`仅将当前增益分最多64帧移动到新目标；48kHz连续输出时为1.333ms。它保留了上述终点，不能消除持续音被整体压低。尾音回收跨档时，又会向较高增益移动，形成音量起伏。

此前为了保持原音量标度，只修改了切档过渡，没有修改原目标表。这是实现范围的局限：稳态与旧版逐位一致，不等于不同复音数下原持续音保持原振幅。单独关闭`HEADROOM_SMOOTH`仍保留这张目标表，只会恢复瞬间切档。

## 改进方向与需要比较的项目

下一项试验应把“每个声部的固定标度”和“总输出过载保护”分开：正常演奏不因声部数变化而调整整个混音；预留明确余量，只有混音峰值接近安全边界时才施加过载保护。保护应考虑左右声道联动，避免一边单独压低而使声像摆动。

固定增益不能同时无条件保证“单音保留任意高响度”和“64个最大、同相样本完全不衰减也不削波”。选定标度和保护方式前，需对实际钢琴片段及最坏相干输入做比较，不能简单永久使用64倍后忽略溢出，也不能仅延长当前斜坡就称为解决。

针对性验证应至少包含：

1. 持续A4，再加入/释放其他音，比较原持续音分量的增益；与ADSR自然衰减区分。
2. 1→2、2→3、4→5及尾音回收跨档，检查是否仍存在按计数产生的整体减半。
3. 保留单音参考响度，分别比较普通和弦、25键交替、64声部及最坏同相满幅输入的峰值、保护动作与失真。
4. 检查左右声道一致性、24位饱和、反压保持、处理周期与实际完整工程时序。
5. 与当前确切R2做同指令、同音高、同力度、同音色的试听，不分别归一化后掩盖音量差异。

本轮只记录定位与改进方向，没有生成新算法或新位流，不声称已经消除了该听感问题。原启动诊断及实板反馈继续保存在[上板排查记录](混音平滑上板异常排查_20261027.md)。
