# 接口V2与队员迁移

版本：2026-09-16。此文中的端口名称、位宽、数值定义对应已实现RTL，是V2对接依据；之前聊天中的`expr_type/expr_value/expr_soure`只是备选示意，本版本没有这些端口。

## 本次交付

新增独立V2工程`TangMega60K_Synth_V2.gprj`，顶层`captain_system_top_v2`。V1工程及其四个RTL接口文件保持原样，队员可以继续运行原有工程。

V2实现：按来源和音符分配声部；三种全局表情参数的握手、缓冲、范围限制、样本边界更新；接入原I2S发送器。它仍然是队长的控制与输出接口，不是实际板级顶层。

未实现：正式DDS/ADSR/混音引擎、幅度平滑、弯音换算、颤音LFO、传感器/ADC驱动、B端事件FIFO、全音停止协议、PLL/引脚与时序约束。因此这是“三维表情控制接口已完成”，不是“三种声音效果已验收”。

## 全局规则

所有接口使用同一个`clk`。只在上升沿`valid && ready`时传输；发送方在`valid && !ready`期间必须保持valid与全部负载不变。复位低有效，板级模块需实现同步撤销；输入、分配器、音源及队列应协调复位，清除旧事件/完成通知。

V1的`cmd_*`、`done_*`、`sample_*`名称、方向、位宽和含义保持不变。6位`cmd_voice`由分配器分配，A无须接收来源编号；64个逻辑声部最终混为左右两个音频声道。

## B → 队长：音符事件

| 字段 | 位宽 | V2定义 |
|---|---:|---|
| event_valid / event_ready | 各1 | 原握手不变 |
| event_on | 1 | 1按下/触发，0松开 |
| event_source | 6 | **新增**，0～63，演奏输入的独立来源编号 |
| event_note | 7 | 0～127，原音符编号，A4=69 |
| event_velocity | 7 | 0～127，note-on力度；0仍按note-off处理 |
| event_timbre | 2 | 0～3，note-on时选择音色 |

来源分配示例：和弦键0～7使用source 0～7，演奏垫使用8～11。一个和弦展开出的多个不同音符可以共用一个source，匹配键是`(source, note)`。

同时按下：source 1的C4、source 2的C4，会得到两个声部。松开source 1的C4只释放它自己的声部。仍按住的相同`(source,note)`再次note-on视为重触发；如希望同一音高的两次动作在按住阶段也独立叠加，上游必须给不同来源，并管理相应note-off。

同来源不同音符可以同时存在。source不是音高，也不是声部编号。对仍按住的`(source,note)`切换音色会按重触发处理，不会因音色不同自动创建新声部。

松开必须携带按下时的原source与原note。B需保存按下时的和弦展开列表；持有期间改变调性/和弦模式不能把松开事件改成新音高。弯音通过表情接口实现，不修改原note。一次性打击也必须有定义好的门控时长和对应note-off，才能进入RELEASE并最终done；不能在仍按住状态直接done。

尾音、满载和完成通知规则沿用V1：release后继续占位直至done，满载拒绝新独立音符，`full_pulse`为一个系统周期。A必须保证每个释放结束只回报一次done，不能回报已被复用声部的迟到done。本版本没有声部抢占或代号机制。

B须排队所有音符事件并检测队列溢出，尤其不能静默丢弃note-off。V2仍只有一个处理中事件，未新增输入FIFO。复位可用于协调恢复，但不是已经实现独立的all-notes-off命令。

## B → 队长：三维全局表情快照

使用**一个完整参数包**更新三个维度，每包同时携带下面三项。B保存三个参数的当前值；改变其中一项时也带上其他两项，避免字段不同步。

| 字段 | 位宽/有无符号 | 数值含义 | 复位默认 |
|---|---|---|---:|
| expr_valid / expr_ready | 各1 | 独立ready/valid握手，不占用音符事件通道 | 0 / 复位时0 |
| expr_gain | 12位无符号 | Q1.11增益：0静音、1024=0.5倍、2048=1倍、4095约2倍 | 2048 |
| expr_bend_cents | 13位有符号 | 整数音分，100音分=1半音；硬件限幅到-2400～+2400 | 0 |
| expr_vibrato_cents | 8位无符号 | 颤音峰值深度，整数音分；硬件限幅到0～100 | 0 |

这里gain是原note-on力度、ADSR之外的全局增益。压力为0时送gain=0会静音；无压力传感器时必须用默认2048，不能随意接0。

这是三种**独立控制参数**：压力改变gain，滑条改变bend，独立旋钮改变vibrato深度。改音色和note-on/off不另外算表情。传感器到参数的映射、噪声过滤和标定由B实现。

颤音速率本版本暂定由A按实际采样率实现固定5 Hz；深度可独立变化，后续再扩展可调速率。gain/bend/depth目前没有在队长模块平滑，A需在音频运算中进行参数平滑以避免突变声。

## 队长 ↔ A：样本边界和生效参数

| 信号 | 方向（相对队长顶层） | 含义 |
|---|---|---|
| engine_sample_begin | 输入 | A在开始计算一个新的左右声道样本帧前发出1个系统时钟周期脉冲 |
| active_gain | 输出，12位无符号 | 已生效的全局增益目标 |
| active_bend_cents | 输出，13位有符号 | 已限幅的全局弯音目标 |
| active_vibrato_cents | 输出，8位无符号 | 已限幅的颤音深度目标 |
| expr_applied | 输出，1位 | 新快照生效的1周期指示，供调试；不是音符触发 |

生效时序：

1. B的表情包完成握手后放入一格缓冲。没有样本边界时，active参数保持不变。
2. 在`engine_sample_begin=1`的上升沿提交参数。**A在下一个上升沿或之后读取新active参数**；在同一个提交沿用非阻塞赋值读取只会读到旧值。建议音源状态机设置PREP阶段提交，再在COMPUTE阶段读取。
3. 如果已有旧包且边界沿又接收到新包，旧包先生效，新包留到下一次边界；不会覆盖已接收但未应用的旧包。
4. 如果缓冲为空、边界沿恰好握手，新包当次提交。没有新包时维持当前值。

同一帧的全部64个声部应使用同一份全局参数快照。A每实际生成一帧只推进一次LFO和全局平滑器，不能每处理一个声部就推进。输出样本在`sample_valid && !sample_ready`时必须保持，不能反复重新生成或推进相位。

`engine_sample_begin`不能直接当作I2S的`frame_tick`：前者是音源计算边界，后者是串行输出边界，I2S前面还可能缓存两帧。必须由音源调度器发出begin，并把缓存与传感器扫描计入延迟。测试台中的恒高begin仅用于测试握手吞吐，不是实际音源接法。

音源侧需要实现的运算：

- 幅度：ADSR与velocity作用后，再乘gain/2048，使用足够宽的有符号乘积并舍入/饱和；gain最大接近2倍，混音必须留余量。
- 弯音：基础DDS频率按音分比例调整。概念关系为`ratio = 2^(cents/1200)`；可用固定点查表/插值实现，不能把Verilog仿真用的real指数函数直接当可综合硬件。
- 颤音：LFO输出的周期性音高偏移乘深度，与bend合成后作用于频率。换算表需覆盖bend±2400加颤音±100的总范围，按真实Fs生成。

gain=2048、bend=0、vibrato=0时，音源应严格保持原先的中性行为。这些参数最终要确实作用到逐样本声音，才能验收三种表情效果。

## 旧队员代码的接法

完全不改动的旧模块可继续使用V1工程。若已经切到V2顶层而B仍只输出旧事件，按下面常量接入新增输入：

```verilog
// V2 instance's NEW ports only; retain existing named cmd/done/sample wiring.
.event_source(6'd0),
.expr_valid(1'b0),
.expr_ready(),
.expr_gain(12'd2048),
.expr_bend_cents(13'sd0),
.expr_vibrato_cents(8'd0),
.engine_sample_begin(1'b0),
.active_gain(),
.active_bend_cents(),
.active_vibrato_cents(),
.expr_applied()
```

这个兼容接法恢复旧的同音合并行为，没有三维表情效果。A先接入V2的cmd/done/sample即可继续联调；完成表情运算后再连接begin和active参数。B逐步增加来源编号、表情快照。不要悬空新增输入，不要用位置顺序实例化跨版本端口。

无需给cmd/done增加source：队长已把来源映射成cmd_voice。这样A现有声部RAM、DDS、ADSR、混音及done回收结构可以继续使用。
