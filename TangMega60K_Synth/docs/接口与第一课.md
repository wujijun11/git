# 队长第一课：把演奏事件分配到声部

> 本文保留为V1接口说明。2026-09-16已新增独立V2工程，支持同音不同来源及三维全局表情参数，见[接口V2与队员迁移](接口V2与队员迁移.md)。旧代码继续使用本文接口；新对接以V2文档为准。

## 模块的作用

可以把64个声部理解成64个演奏位置。分配器决定哪个位置开始演奏、哪个进入释放阶段，
声音的相位、频率计算和ADSR由队员A的引擎完成。

```text
队员B：触摸、压力、倾斜 → event_* → 你的分配器 → cmd_* → 队员A：合成引擎
                                            ← done_* ← 包络释放结束
```

## 统一约定

所有信号属于同一个clk时钟域。复位低有效；整机集成时需由板级模块同步撤销复位，
且分配器和音频引擎必须一起复位，以免声部所有权不一致。
只有在上升沿 valid=1 且 ready=1 时发生传输；valid=1、ready=0期间发送方必须保持所有字段。

### B → 队长：演奏事件

| 信号 | 位宽 | 含义 |
|---|---:|---|
| event_valid / event_ready | 各1 | 事件握手 |
| event_on | 1 | 1为按下；0为松开 |
| event_note | 7 | 音符编号0～127；约定A4=69，C4=60 |
| event_velocity | 7 | 0～127；按下且力度为0视为松开 |
| event_timbre | 2 | 音色编号0～3；具体音色由团队约定 |

本版本不读取传感器，也不缓存下一条事件。B需保留待发事件或通过FIFO排队，
不可只发送一个时钟脉冲后不管ready。和弦展开为多条音符事件。
相同音符的两个独立琴键在本版会合并，后续支持此用法需增加key_id/channel。
压力持续变化与全局滑音属于下一阶段控制接口，不应通过重复note-on模拟，否则会重新触发ADSR。

### 队长 → A：声部命令

| 信号 | 位宽 | 含义 |
|---|---:|---|
| cmd_valid / cmd_ready | 各1 | 命令握手；A必须能接收release命令，不能等声音结束才ready |
| cmd_on | 1 | 1开始/重新触发；0开始RELEASE |
| cmd_voice | 6 | 声部0～63 |
| cmd_note | 7 | 引擎据此换算频率控制字 |
| cmd_velocity | 7 | 按下力度；release时不用它更新原力度 |
| cmd_timbre | 2 | note-on时使用；release命令不要改变原音色 |

同一声部只有一份状态。新的note-on命令重设包络的规则由A统一实现，避免卡音。
当前模块只保证命令正确、顺序一致，不保证重触发时听感无咔哒声。

### A → 队长：释放完成

`done_valid / done_ready / done_voice[5:0]`：仅在对应声部RELEASE真正结束后发送一次。
valid要保持到ready握手，不能把“声部空闲”一直当成新的done事件重复上报。
满载时也必须能发送完成事件，避免系统无法回收声部。
不接受仍按住声部、已空闲声部的完成报告；输出done_error_pulse。
不允许已完成并被复用的旧命令再产生迟到的done；后续加入抢占时须增加代号防止此竞态。

### 调试状态

- active_count：已占用声部数（包含尾音）。
- active_mask：每一位代表该声部是否被占用。
- held_mask：每一位代表是否仍按住；held一定是active的子集。
- full_pulse：新音符被拒绝；仅1时钟，可接累加器，不可直接接LED期望肉眼看见。
- ignored_pulse：没有匹配的按住音符，忽略松键事件。
- done_error_pulse：非法/重复/过早完成通知。

## 状态机

1. IDLE：优先接收释放完成，否则接收一条演奏事件。
2. SCAN：每时钟检查一个声部，找最低编号空位和同音按住声部。
3. DECIDE：选择目标；无目标则报告满载或忽略松键。
4. SEND：保持命令直到A接收，再更新占用状态。

64声部时，输入事件被接收后经过64个扫描周期、1个决策周期，命令变为有效；
若cmd_ready一直为1，再下一个上升沿完成接收。仿真采用50MHz，66周期约1.32us。
这只是分配器延迟，不是传感器到DAC的端到端延迟，也不是对板上Fmax的证明。

## 第一次看波形

1. 初始rst_n=0，active_count=0。
2. 第一个事件使用音符36、力度100，分配cmd_voice=0。
3. 测试故意让cmd_ready保持0，检查cmd_valid及命令字段不变。
4. cmd_ready变1并握手后，active_count变1。
5. 再按相同音符，仍分配0，active_count不增加。
6. 松开后held_mask[0]清零，但active_mask[0]仍为1。
7. A通过done握手报告结束，active_mask[0]才清零。

## 当前验证覆盖

自动测试分别使用4和64声部，覆盖首次分配、同音重触发、无效完成、释放尾音占用、
尾音期间同音再次按下、重复完成、力度零、未知音符松开、满载拒绝、
最后一个槽位回收及复用、完成与输入同时出现的优先级、命令反压和发送中复位。
每个周期检查active_count与active_mask位数一致，held_mask不越出active_mask。

综合只验证控制逻辑能映射到目标器件，尚未运行带实际约束的布局布线或进行上板测试。
