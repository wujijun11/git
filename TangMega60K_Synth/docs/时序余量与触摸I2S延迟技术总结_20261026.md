# 时序余量优化与触摸到I2S延迟专项

## 基线与范围

以本地OLED完整工程为基线，保留 `delivery-oled-integration` 的位流与源码。
本轮位于独立本地仓库 `test-timing-latency-20261026`，分支 `codex/timing-latency-oled`。
先在该分支保存OLED基线提交 `4bee4c9`，再保存本轮测试改动；main与发布仓库不修改、不推送。
原 `比赛 2/TangMega60K_Synth` 的生产RTL和仿真入口已经恢复OLED版，测试脚本与候选只在独立仓库继续维护。
基线Setup最小余量0.046ns、Hold 0.001ns；逻辑27991、寄存器18361、BSRAM105/118、DSP51.5/118。
本次不修改引脚、PLL、49.152MHz音频时钟、48kHz采样率、24位PCM、八成分钢琴参数或音量标度。
新构建在独立英文目录执行，只有实际通过功能回归和时序检查的版本才整理为新交付。

这里有两种不同的时间：**时序余量（ns）**表示电路每拍计算、传递能否赶上时钟；**演奏响应（ms）**表示从输入识别到音频输出要等多久。增加中间寄存器可以让每段电路更容易赶上时钟，即使多一拍也只有约20.35ns；本次触摸响应主要等待在串行读取和采样帧，并不是这些寄存器耗掉几毫秒。

## 模块与修改原理

| 层次 | 文件 | 职责与原因 |
|---|---|---|
| 音源状态存储 | `rtl/audio/polar_lane.v` | 原上升沿暂存后增加下降沿搬运寄存器，仍在原定下一上升沿写RAM。算术保留一整周期，RAM输入获得半周期稳定窗，针对同沿寄存器到RAM的极小Hold余量；须由实际STA检查两个半周期路径 |
| 曲谱命令校验 | `rtl/performance/performance_controller.v` | TRANSPORT格式、busy与内容判断并行计算，动作范围只比较低4位，高76位单独归约。保持“格式错误优先、忙优先于内容错误”的状态码与执行拍次 |
| 录音回放行译码 | 同上 | 只给MODE_REPLAY增加行与键号的寄存边界，录音来源减法前移；索引、模式同时锁存，标签不匹配时等待，避免切换或换行消费旧行。录音回放最多增加一拍准备时间，约20.35ns；上传曲谱、内置曲谱和学习保持原逐行吞吐量 |
| 键号到音高/所有权 | 同上 | 将可变位选 `key_map_flat[active_key*7 +:7]` 与held数组选择改为25个固定索引并行译码后按位或，缩短桶形移位/选择链，不增加等待拍；合法键号0..24，直接曲谱的MIDI0..127仍走原独立旁路 |
| 本地停止握手 | `rtl/instrument_full_system.v` | 本地PANIC=5始终无busy条件，使用其执行握手短路径，不让80位命令格式归约穿过通用ready返回FIFO写使能；其余动作ready/status不变，`tb_global_panic`逐拍核对新旧判定一致 |
| 参考模型 | `sim/polar_lane_timing_reference.v`、`sim/performance_controller_timing_reference.v` | 冻结OLED交付源码，文件头记录SHA256，仅用于仿真，不加入综合工程 |
| 音源等价 | `sim/tb_polar_lane_margin_equivalence.sv` | 核对两个lane的输出有效拍、左右样本、元数据及各自256行私有状态，覆盖64声部地址、四音区、复位、同址读写、包络段切换；还注入输出错误和提前半拍写RAM，检查测试台确实能拒绝错误 |
| 状态等价 | `sim/tb_transport_status_equivalence.sv` | 穷举0..255动作、512种内部状态及高位格式错误，同时检查学习功能开启/关闭，与冻结模型比较 |
| 全局停止回归 | `sim/tb_global_panic.sv` | 在原UART/实体事件/排空测试上，增加本地PANIC新旧接受条件逐拍比较 |

写RAM没有提前到下降沿；提前写会改变同址读旧值语义，已有负例专门检查。下降沿寄存器不是新时钟源，仍用原音频时钟，未增加PLL，也不添加多周期/假路径来掩盖计算路径。

## 延迟测量边界

旧 `tb_board_key_latency` 测板载机械KEY输入，并不能代替25键MPR121触摸链路。
新专项必须覆盖“触摸状态寄存器改变→真实I²C读取→快照→触摸事件→FIFO/分配器→引擎→I2S输出”。从导出的BCLK/LRCLK/DATA解码完整24位样本，不把内部valid或任一高电平当作已经输出。

数字从机模型只模拟已滤波触摸状态，不模拟人的手指、电极电容、MPR121模拟前端及滤波。其耗时不能被写成0。生产寄存器0x5D=0x20，对应SFI=4、ESI=1ms。NXP说明二级滤波响应与SFI×ESI相关；这不能直接证明真实琴键总延迟≤5ms。具体物理触摸到DAC/喇叭仍需要示波器或逻辑分析仪配合同步触发实测。[NXP AN3890](https://www.nxp.com/docs/en/application-note/AN3890.pdf)

初始化等待允许在测试台缩短以控制仿真时间；进入ready后必须保持生产400kHz I²C、0.5ms轮询、64声部、原ADSR和实际I2S分频。记录不同轮询相位、三组传感器和同时多键条件，分别报告最大观测延迟与抖动，不把有限场景写成严格最坏上界。

本测试把初始RESET等待缩为8拍、稳定等待缩为1ms、校准快照缩为1次；这几个修改只存在测试台defparam中。1ms仍长于正常0.5ms轮询，且测试台显式断言常态I²C、轮询、声部数、ADSR和I2S分频没有加速。屏幕、音源、分配器及三条传感器总线都在完整顶层中，I²C快照没有被force替换。

## 以后怎样上板验收延迟

1. 先确认板上运行本次位流，记录文件SHA256、下载时间、音色和音区。
2. 用逻辑分析仪同时采MPR的IRQ、该总线SCL/SDA及音频BCLK/LRCLK/DATA，核对识别后到实际串行样本的延迟、漏音、帧长和长时间欠载情况。IRQ起点只能覆盖“传感器已识别”之后，不能证明手指总延迟。
3. 真实触摸总延迟需要可重复触摸激励的同步起点，并测DAC模拟输出或声学输出；这部分方案和仪器尚未实施。应覆盖三组传感器、轻触/快速重触发、和弦及负载，不只测一次平均值。
4. 分别报告最小、最大、分布和偶发异常。当前轮询相位会造成数字通路变化，不能仅凭固定系统时钟声称演奏延迟“确定且无抖动”。
