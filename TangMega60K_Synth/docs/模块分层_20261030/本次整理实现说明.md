## 实现方式

1. 只读获取当前Git跟踪文件和未忽略的新代码，不限于HEAD，因此包含本地尚未提交的延音功能。
2. 从full/ContestFull.gprj解析实际启用的HDL列表，逐一确认文件存在。
3. 复用catalog-submission-sources.py的注释清理、module和实例解析函数，建立静态父子关系。
4. 从board_contest_full_top遍历，区分完整顶层关系中的文件与独立/历史入口。
5. 复用既有逐文件用途资料，补齐/修正新增菜单、波形、后台播放、固定增益和延音模块的说明。
6. 分别列出界面、通信协议、业务逻辑、数据处理、存储、硬件驱动及测试工具，保留原有路径。

解析不展开generate条件、参数复制或厂商原语，因此65个“静态可达文件”不是65个实际硬件实例。
对当前禁用的旧平滑、平面菜单和内部延迟分支作了明确说明，不能凭文件名推断当前算法。

## 发现的问题与处理

| 问题 | 本次处理 |
|---|---|
| 工程列有许多旧顶层，容易误认为同时工作 | 将90个文件分成65个静态可达、25个当前完整顶层未实例化文件，并解释条件分支。 |
| 旧用途清单没有新增模块，部分说明仍描述旧混音 | 为新模块补用途；标明当前固定增益优先、旧headroom_smoother分支未启用。 |
| 工作区与发布副本GAO状态不同 | 标注开发GPRJ保留调试条目，而本次冻结构建通过--without-gao禁用GAO；没有擅自改文件。 |
| Flash旧排查记录仍写“未恢复” | 在原记录顶部追加用户2026-10-30已修复反馈，原排查内容保留为历史，未编造根因。 |
| 物理移动目录可能破坏工程和ROM路径 | 采用职责分类文档和链接，实际源码保持原位置。 |
| 中文控制台输出可能受Windows默认编码影响 | 使用Python的-X utf8运行清点工具，文档统一UTF-8。 |
