# 模式同步与蓝牙延迟修正

后续实测与Windows/Android/C3优化见《蓝牙延迟优化与测量_20261025.md》。下文“尚无工具链”的限制为上一阶段记录；完整C3编译是否通过以新交付 `c3/build-manifest.json` 为准，未因此宣称C3实物已更新。

## 演奏处理修正

之前曾取消“尚未发送就已松开”的按键，会导致快弹漏掉整个短音，不能作为降低真实延迟的方法。该策略已撤销：正常按下、松开按顺序完整发送。只有明确全停、主动断开和通信失败才取消旧操作。

延迟确认测试连续发送50组按下/松开，100条事件全部保留并按顺序发送；另验证重按、多持有者和释放批次。这证明没有主动丢弃短音，不证明真实无线已经变快。若链路吞吐小于输入速度，仍会排队；队列超过128会明确报错关闭，不静默漏音。

## 模式显示

按用户确认，电脑或手机任选一个连接C3；未扩展为两个客户端同时控制。新版显示板上的总菜单/子页、音色、音区半音、录制/播放/指引/待机及切换忙状态。空闲时约每秒读取一次，演奏或上传忙时顺延。

连接时先探测能力。支持新回传时采用板上的音色和效果，不用客户端默认值覆盖滑条选择。旧版返回不支持后仍可控制，但不把客户端选择冒充板上状态。读取只更新显示，不触发CONFIG写入。原有连接全停、重新配置键位/表情仍保留；增益、弯音、颤音和完整键位尚未增加只读同步。

协议仍是16字节帧、CRC和应用层ACK。新增READBACK（08）selector02、索引0，ACK后返回83快照；原0/1查询和公共音源V2接口不变。载荷如下：

| 字节 | 含义 |
| --- | --- |
| 0 | 格式版本1 |
| 1 | bit0总菜单、1忙、2播放、3录制、4指引、5菜单启用；其余0 |
| 2 / 3 | 页面 / 区域，0..3 |
| 4 / 5 | 实际音色0..3 / 有符号8位半音，例如-12编码F4 |
| 6 / 7 | 效果0..3 / 最近菜单错误码 |
| 8 / 9 | 保留0 |

`remote_command_router.v`默认关闭扩展，主工程显式开启并接入滑条/App仲裁后的实际状态。请求锁存整份快照；反压和同序号重试保持一致，新序号才重新采集。客户端检查版本、保留位和数值范围。

电脑 `controller.js`负责连接/只读查询/测时，`protocol.js`负责解码，`app.js`负责显示；手机同样由协议与界面分工。断开后显示未连接，不保留旧状态冒充实时状态。

## 延迟检查与候选优化

电脑显示本机排队、请求至确认时间，日志导出最近256条测时；原生驱动另记录写入耗时。“收到确认”不等于DAC实际出声，整机发声延迟需实测。

C3候选优化在 `bridge_notify_policy.h` 和 `ble_bridge.ino`：成功通知不再强制间隔15ms，循环仍有1ms让步；失败保留15ms退避、错误计数和队列保护。另声明可选无ATT写响应，电脑只在设备明确支持时使用，旧设备保留原写法。每条命令仍等FPGA应用ACK，并保留重试，没有无界并发。

依据：[Bleak写接口](https://bleak.readthedocs.io/en/latest/api/client.html#bleak.BleakClient.write_gatt_char)、[Espressif属性说明](https://github.com/espressif/arduino-esp32/blob/master/libraries/BLE/README.md)。原生驱动假GATT测试验证两种写法均完整等待写入、保持原16字节帧、拒绝旧会话；主机C++测试覆盖通知节流、失败退避和毫秒回绕。

**尚未找到本机ESP32工具链；C3候选固件未完整编译、未刷入、未实测无线。** 主机策略测试不代表ESP32固件验收。只更新电脑、继续使用旧C3时，不会自动去掉固件里的15ms等待。当前没有宣称真实卡顿已解决或快歌已达到某个延迟指标。

## 实际验证范围

- 5项ModelSim：模式快照、原控制、整机、全停和64音菜单通过；另2项核对实际音色/音区连线及快照。
- 电脑测试：板端模式优先、负音区、空闲刷新、无隐式配置、坏帧和旧版兼容；正常短音完整发送、全停、断开、重按。
- 手机独立390像素浏览器：采用板端模式、空闲刷新、读取不回写；原重连及上传回归。
- Windows打包自检与Android1.4编译/lint/开发签名校验；不等于真实BLE和发声验收。
- 新RTL布局布线结果见新版清单。遇到中文路径不兼容后保留失败日志，转到临时英文目录运行相同源码，没有放宽SDC。

板卡未自动下载，手机未自动安装。OLED引脚和噼啪声实测仍待处理。
