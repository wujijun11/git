## 检查得到什么，尚不能断定什么

与基线`20aa6f9`相比，原平滑版生产修改只有：新增平滑模块、音源中可选接入、完整系统启用参数、GPRJ加入该文件。C3、Windows/手机、UART源码、板级引脚、PLL源码与SDC没有改动。实际综合网表的三组PLLA倍分频参数也已与原版逐项查看，一致。

但是重新综合/布局布线会改变整个实现，不能由“源码没改PLL”推导为“上板时钟和复位一定没问题”。Setup/Hold为正也不是已经通过实板验收。

实体传感器与UART都运行在49.152MHz域，共用板级`rst_n`。原RGB发送器运行在独立50MHz，默认淡绿色不取决于音频PLL是否已经运行。因此绿色不能排除音频域未启动或一直复位。这是排查优先方向，**不是已确认PLL根因**。新的混音数据不直接控制UART复位；音频通路的局部复位也不直接复位UART。

仿真存在明确边界：`audio_plla_stage`在`SIM`条件下跳过实际PLL_INIT动态初始化，原厂模型不提供真实MDRDO；整机板级测试因此不能证明本次硬件PLL启动过程已经正确。原42项实际仿真结果保留，但不能用它们覆盖这次实板失败。

## 临时诊断模块与职责

本分支`codex/headroom-board-triage`只增加启动观察，不改变平滑算法，不把临时诊断版称为修复版，不上传main或自动下载。

| 文件 | 作用 |
|---|---|
| `rtl/board/audio_boot_status.v` | 在独立50MHz读取既有48位双级采样快照，检测音频心跳，并生成RGB状态 |
| `rtl/board/board_contest_full_top.v` | 本分支新增`BOOT_DIAGNOSTIC=1`选择诊断颜色；其他音频/通信连接不变 |
| `full/ContestFull.gprj` | 加入诊断模块；不改CST/SDC/PLL参数 |
| `sim/tb_audio_boot_status.sv` | 人工快照验证颜色优先级、心跳停转及恢复；不能当真实PLL测试 |
| `scripts/test-modelsim-full.ps1` | 登记上述用例，与板级、音频和通信相关回归一起运行 |

既有快照低位含`board_ready[0]、audio_locked[1]、ready_sync[2]、rst_n[3]、audio_rst_n[4]`，心跳位为44，传感器ready/fault分别为18:16和21:19。没有增加跨域功能控制。心跳取既有音频计数器bit8，正常约5.2μs翻转一次、周期约10.4μs；超100ms未观察到翻转则判为停转。这里使用普通寄存器计数器，无块RAM或历史记录。

## 诊断版颜色表

此表仅适用于独立启动诊断位流，覆盖原模式灯色。

| 颜色 | 观察含义 |
|---|---|
| 白 | 独立50MHz上电等待尚未结束，正常只持续很短时间 |
| 红 | 两级音频PLL综合锁定资格尚未成立，不能据此直接区分哪一级 |
| 蓝 | 尚未见音频心跳，或心跳停止超过100ms |
| 紫红 | 音频心跳存在，但顶层仍处于复位或ready尚未同步 |
| 黄 | 顶层已运行，但音频局部通路仍被panic/传感器溢出复位 |
| 青 | 公共启动链正常，但传感器未全部就绪或报告故障 |
| 绿 | 音频心跳、复位释放和传感器就绪；不证明UART握手或声音已正常 |

没有音频时钟时，50MHz灯色逻辑仍能显示红/蓝。多位状态是诊断快照，刚下载的短暂变色不算稳定故障；观察约3秒后的稳定颜色，并记录键盘与握手是否正常。
