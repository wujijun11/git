# 5×5灯位图与琴键编号（Windows 1.4.3）

## 用户会看到什么

在“演奏”页向下滚动到25键演奏区域，上方出现5×5灯位图，下方琴键显示同样的01–25编号。
编号指固定键位，从左到右包含黑键，不能只数白键。改变音区或MIDI映射不会改变编号。
灯位图的小字是键位映射的音名；板上另加的音区偏移不包含在这个映射音名中。

点灯图的08，下方琴键08出现紫框，并显示“灯位08 ↔ 琴键08”。这只帮助找键，
不发送演奏命令、不改映射、不点亮实体灯。点“清除定位”去掉紫框。

选内置曲谱或25键映射曲谱，再在灯图旁点“灯光指引”。软件先准备所选曲谱，
FPGA开始独立按节奏运行灯光指引，电脑同时显示跟谱目标。绿色对应当前应该按的键，
例如“08 + 12号键”表示同时按两键；休止显示“松开，等待下一拍”。再次点击停止。
指引不替用户自动发声，实际演奏仍走现有纯HDL音源。

## 实物编号怎么贴

1. 在浏览器打开随包的 `25灯与琴键编号贴纸.html`，按Ctrl+P打印。默认圆标签直径约12mm，
   可按空间缩放；纸张是编号辅助，不是PCB孔位或外壳尺寸图。
2. 一组贴琴键旁，一组贴灯旁，不覆盖触摸电极或灯珠发光面。
3. 灯板尚未到货，先不要按假定方向永久粘贴。拿到后用原25灯校准JSON确认位置和方向。
4. 目标布局为上排01–05，第二排06–10，直到下排21–25。若实际是蛇形或转向排列，
   应按校准结果设置既有 `GUIDE_PIXEL_KEY_MAP`，这一步涉及重新构建FPGA位流。

如果25键是一字排开，需要在灯图与键盘之间看编号；每键独立灯更直观，但本方案保留现有5×5整板。
屏幕的5×5图是逻辑布局，无法自动识别尚未接入的灯板方向或型号。

## 为什么标为“跟谱估计”

现有状态帧只有guide、playing、scorePosition等字段，没有板端时间戳、25位灯掩码、
物理触摸掩码或曲谱ID。软件不会把本地动画说成真实灯色或已弹对反馈。

启动时冻结这次曲谱，累加每条deltaMs得到事件时间，逐条计算每个时刻的目标键集合。
相同时间的多条按键事件一起显示；力度为0的NoteOn按释放处理，与RTL一致。
按已有心跳收到的scorePosition校正估计时间，不追加高频查询，不用灯图事件占据蓝牙队列。

限制与保护：

- 需要从这个电脑页面发起指引。由滑条发起或重连后的曲谱身份无法确认，只显示运行状态，不套用本机选择。
- 内置曲谱表对应当前仓库的performance_controller.builtin_row；不同固件内置谱可能不同。
  要跨版本核对，优先上传已知的25键校准或自定义曲谱。
- 蓝牙往返时间、系统调度和板端停顿会影响估计，不保证与实体灯严格同步。
- 超过1800ms没有新状态，清除屏幕目标并显示等待回传；这不代表板上指引已停止。
- 停止、断开、异常倒退/越界位置会清除目标。没有曲谱ID，无法识别所有来自本地菜单的替换操作；
  跟谱期间不要同时从滑条换曲或重启。要换曲先停止，再从本页开始。
- 直接音高和实时长曲谱仍不提供25键指引；本轮也没有“等弹对再继续”、提前预告或评分。
- 实体灯既有绿色/蓝色/青色的含义不变；屏幕紫框只表示用户正在查找编号，不代表触摸。

## 文件和职责

| 文件 | 职责 |
| --- | --- |
| desktop/web/guide-timeline.js | 纯数据层：曲谱快照、目标掩码、回传校正、过期和异常保护 |
| desktop/web/guide-panel.js | 界面层：5×5网格、编号、定位、键盘高亮及状态文字 |
| desktop/web/guide-panel.css | 图形和窄窗口样式，沿用已有字体及配色 |
| desktop/web/guide-control.js | 指引业务；在启动前通知界面绑定本次曲谱，通信仍复用控制器 |
| desktop/web/app.js、index.html | 初始化模块、连接按钮/回传/停止/断线回调、加载资源 |
| desktop/web/guide-labels.html | 独立可打印的两套编号和5×5对照卡 |
| desktop/tests/test_guide_timeline.cjs | 时间、和弦、重复音、校正、失联和异常单元测试 |
| desktop/tests/test_guide_map_ui.cjs | 浏览器端编号、定位、高亮、断线、窄窗口和打印页测试 |

主程序只做接线，时间计算与界面绘制独立。没有改动FPGA RTL、音源算法、引脚约束、
手机端或C3程序，使用原完整主工程即可，无需仅为本界面重新下载.fs。
实物灯位校准改映射另需新位流，不能与本次纯上位机修改混淆。
