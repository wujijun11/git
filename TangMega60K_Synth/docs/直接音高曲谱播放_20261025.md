# 可选的直接音高曲谱播放

一首曲子先后出现30、50或128种音高，与“同一时刻发声多少个音”不同。25个实体琴键限制的是原键位曲谱映射，不是音源能处理的音高总数。新模式直接保存MIDI0–127音符及力度/时间，FPGA逐事件调度，经原声部分配器、DDS/八成分钢琴等音源、ADSR、效果和I2S输出；没有PCM音乐播放。

## 怎么用

1. 先下载此次通过构建验收的 `ContestFull_DirectScore1024.fs`；仅更新电脑软件不能让旧FPGA自动支持新格式。C3继续透明转发16字节帧，不需要为此换固件。
2. 电脑使用1.3.0-local，手机使用Android1.7。搜索/推荐或打开本地MIDI，选择音轨、开始/结束时间。
3. 勾选“脱离25键直接播放”，点击分析，确认提示后导入，再明确点击上传和播放。软件上传前先查询能力；旧FPGA返回不支持时，上传会在停止/清空曲谱/键位操作之前拒绝。
4. 使用板上当前音色。改变音色影响后续新触发音符，已发声的音保留其声部音色。实体滑条音区不会转调直接模式的MIDI音符；全局增益、弯音/颤音及音效仍按现有通路生效。
5. 取消勾选恢复原25键映射模式。原键盘、录制/回放、灯光指引和上传格式保留。

直接播放不修改实体键位，不将MIDI音高硬压到25键；也不提供“哪个琴键该亮”的指引，因为超出的音没有对应按键。实体触摸反馈灯仍可显示。直接曲谱请求纯指引模式会返回无效参数。

## 仍然存在的限制

- 曲谱RAM仍是1024条事件，一次按下、一次松开通常共两条。音高种类多不代表事件容量无限；超限仍需选择片段，不静默截断。
- 共用64声部，实体演奏和远程演奏也会占声部，释放尾音尚未结束时也占用。转换器检查同时按住的音符，超过64拒绝；不能仅凭这个检查保证密集尾音永不满载。未增加抢占或改变原音量标度。
- 同一音高在多个MIDI音轨重叠时沿用既有合并策略；踏板、Program Change和原乐器音色等仍不导入。只使用当前FPGA音色，非通用MIDI音源。
- 格式支持MIDI0–127，但极低/极高音的可听程度受喇叭、采样率、已有音色分区影响；没有宣称全音域都达到真实钢琴听感。
- 本次软件模拟、RTL与构建检查不代表已上板、蓝牙全曲或DAC实测通过。下载前保留旧 `.fs`，本次未自动下载硬件或推送远端。

声音实时生成部分及公共V2 `event_* / cmd_* / done_* / sample_*` 端口保持。新增 `local_action_status` 只是内部曲谱控制模块给本地菜单的状态线，让菜单不经过1024行上传校验的组合路径，不改变外部演奏协议。

完整集成增加命令寄存边界和高扇出音频复位寄存器：正常命令增加一拍约20.35ns，全停时入口立即切到丢弃端并禁止FIFO写入，音频复位至多后一拍生效。PANIC排空与按键隔离仍保留。`performance_stage` 单独验证不能提前ACK、负载反压稳定、来源优先级、忙状态回传和复位；全停测试保持“立即禁止新命令/事件”，音频复位断言改为检查一拍内完成。

## 线协议增量

沿用16字节帧、CRC、序号、ACK/重试及反压。没有新音频推流。

| 请求 | 扩展 |
| --- | --- |
| READBACK08，selector3，index0 | 返回ACK后0x84能力。旧FPGA拒绝，客户端不得继续直接上传 |
| 0x84载荷byte0..9 | `01 01 容量低 容量高 7F 40 3E 00 00 00`：版本1、能力bit0、容量、最高音符127、声部64、独立来源62 |
| SCORE_WRITE06 | 原byte6键位、byte9=0不变；直接格式byte6=MIDI0..127、byte9=1，其余字段仍为indexLE16、deltaMsLE32、velocity、on |
| SCORE_COMMIT07 | selector0为原键位上传，1为原内置曲谱，2为直接音高。count仍为LE16 |

新客户端每次上传先停止，再选择内置曲谱以清空上传批次元数据，然后逐行上传，最后提交；不会自动播放。取消后不得提交半份用户曲谱。新RTL检查同一批次不能混合两种行格式，并按提交格式校验。中断后重传从新批次开始，25键映射不受直接上传影响。

直接播放使用来源62，与键位曲谱0..24、实体25..49、远程演奏63分开；分配器按 `(source,note)` 匹配。保存128位“已发NoteOn”表，停止时逐音扫描发NoteOff；不复制128个音源。输出受阻时所有事件字段保持，停止过程中已呈现的事件先完成握手，然后释放；重新开始须等待排空。

工具需已安装。Windows中文路径不兼容时使用提供的英文临时快照脚本，保留原工程和已验证实现。

```powershell
./scripts/verify-direct-score.ps1
# 带完整布局布线，GAO只在隔离副本关闭，原CST/SDC不放宽：
./scripts/verify-direct-score.ps1 -Build
./tmp/desktop-python/Scripts/python.exe -m unittest discover -s desktop/tests -p test_direct_midi.py -v
node desktop/tests/test_direct_score.js
./tmp/desktop-python/Scripts/python.exe mobile/tests/make_midi_fixtures.py
node mobile/tests/test_midi.js
node mobile/tests/test_app_async.js
node desktop/tests/test_direct_ui.cjs
```

新增ModelSim用例：`direct_score`（真实64声部分配器、假音源完成释放，用于调度），`direct_capability`（能力查询、重试与反压），`direct_system`（真实UART、分配器、音源、PCM和I2S）。后者验证32个直接音符与一个同音高远程音符同时保持，停止只释放直接来源，极端音符0/127和原键位不变。
