# 第三阶段：实时测试音源到 I2S

本阶段为队长准备独立的音频通路诊断工程，不依赖队友代码、不需要开发板。正式音频引擎接入时替换测试音源，原有控制器接口和 `captain_system_top` 保留。

## 做了什么

`test_tone_source` 使用 32 位相位累加器实时计算三角波，不播放预录音频。相位只在 `sample_valid && sample_ready` 时前进；缓冲满时样本保持不变。音源通过 `tone_demo_top` 接入第二阶段的 `i2s_tx`。

默认左右均为 A4（440 Hz），峰值约为满幅的 1/8。测试台单独把右声道设置成 660 Hz，以识别左右声道混淆。它是通路测试音，不包含乐器音色、ADSR、多复音或传感器控制。

频率控制字：`round(频率 × 2^32 / 采样率)`。在 48 kHz 下，440 Hz 对应 39370534，660 Hz 对应 59055800。频率随实际采样率变化。

## 如何操作

在 ModelSim Transcript 中输入，第一行换成本机实际目录：

```tcl
cd {C:/Users/asus/Desktop/Git/TangMega60K_Synth/sim}
do waves_tone.do
```

脚本运行到 5 ms。观察 `decoded_l` / `decoded_r`，可以右键将波形显示格式改成 Analog 查看三角波；`serial` 是 I2S 数据位，不是模拟音频幅度。`underruns` 应为 0。

在项目目录 PowerShell 执行完整回归和试听导出：

```powershell
./scripts/test.ps1 -ModelSimBin 'D:/msim/modelsim_ase/win32aloem'
./scripts/export-tone.ps1
```

导出 `sim/tone_preview.wav`：24 位立体声、48 kHz、0.25 秒，左 440 Hz / 右 660 Hz。样本来自仿真对 I2S 引脚的串行解码，不是脚本另算的音频。必须先完成整个测试；只运行 5 ms 的波形演示会生成不完整 CSV，不能导出。

部分播放器会将 0.25 秒显示为 0 秒。脚本同时生成 `sim/tone_preview_5s.wav`，将原始片段重复 20 次并转换成 16 位 PCM，首尾加 10 ms 淡入淡出，便于试听。该文件不代表进行了 5 秒 RTL 仿真；原始 24 位数据仍保留。

## 检验方法

1. 用样本序号和数学三角波参考逐样本比较左右串行解码值，不读取 DUT 相位来计算预期值。
2. 检查 I2S 延迟位、补零、帧周期与连续供数无欠载。
3. 检查 ready 拉低期间的样本稳定性。
4. 发送 64 帧后在帧中复位，验证音源与输出缓冲一起重新开始。
5. 复位后解码 12000 帧，左声道上行过零 110 次，右声道 165 次，验证音高。

## GOWIN 与硬件边界

`ToneDemo.gprj` 是独立的诊断工程，顶层为 `tone_demo_top`。可用 `scripts/synth-tone.tcl` 做综合。原队长工程不被替换。
