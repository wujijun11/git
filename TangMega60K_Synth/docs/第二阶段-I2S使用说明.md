# 队长第二阶段：把合成样本送到 DAC

本阶段已完成 RTL、串行解码仿真及 GOWIN 综合，不需要队友代码，也不需要连接开发板。
目标仍是 Sipeed Tang Mega 60K。真实 DAC、板级时钟、引脚与音色效果留到硬件集成验证。

## 先理解连接关系

```text
队员B：传感器/按键
          │ event_*：音符与力度
          ▼
队长：64声部分配器 ── cmd_* ──► 队员A：实时合成引擎
          ▲                       │ 64声部计算、包络、混音
          └──── done_* ────────────┤
                                  │ sample_valid/ready + 左右样本
                                  ▼
                         队长：2组立体声样本缓冲
                                  │
                         队长：I2S 逐位发送器
                                  │ BCLK / LRCLK / DATA
                                  ▼
                               音频 DAC
```

64复音指64个独立音符可以同时发声；最终可以混成立体声左右两个声道。
I2S发送器不计算音高、ADSR或音色，它负责把已经合成的样本准确送出去。
本阶段样本来自测试台中的模拟发送方，不能当成已经完成64振荡器实时发声。

## 与队员A约定的样本接口

所有信号属于同一 `clk` 时钟域，复位为低有效 `rst_n`。

| 信号 | 方向（相对队长） | 位宽 | 含义 |
|---|---|---:|---|
| sample_valid | 输入 | 1 | A已经准备好一组左右样本 |
| sample_ready | 输出 | 1 | 当前可以接收这一组样本 |
| sample_left | 输入 | 24，signed | 左声道二进制补码样本 |
| sample_right | 输入 | 24，signed | 右声道二进制补码样本 |
| frame_tick | 输出 | 1 | 新立体声帧开始，持续一个系统时钟，可作为调试/调度参考 |

握手规则：只在 `clk` 上升沿 `sample_valid && sample_ready` 时接收一次。
当 valid=1、ready=0 时，A必须保持 valid 与左右样本不变，直到成功接收。
不能只打一拍 valid 后就丢弃；也不能把 ready 当作采样时钟。

给A的实现建议：准备下一组样本 → 保持valid → 握手成功后推进样本序号，再生成下一组。
启动时可预填缓冲；平稳运行时每帧只消费一组样本。内部合成可以流水线运算，输出样本必须保持顺序。
零音量时也持续提供左右全零样本，这属于正常静音，不会增加欠载计数。

不要把“等待下一次frame_tick才送当前帧样本”当作及时供数：frame_tick出现时当前帧已经选好样本。
它可以通知A准备后续帧；是否来得及，最终由握手与欠载计数判断。
跨时钟域时需另加异步FIFO，不能直接跨域连接这些多位信号。

## 本版音频格式与时钟

- 标准 Philips I2S：WS/LRCLK=0为左，=1为右，最高位先发。
- WS改变之后留一个位时钟，再发送新声道的MSB；DAC在BCLK上升沿取数。
- 每声道32个位时钟，其中24位有效补码数据，其余补零。
- 左右一帧共64个BCLK；每帧一组新的左右样本。
- 所有寄存器都由系统clk驱动，BCLK仅作为输出，避免在本模块引入新内部时钟域。

```text
某声道时隙：  0    1     2   ...  24    25 ... 31
WS：         改变 ──────────────────────────────
DATA：        0   bit23 bit22 ... bit0   0 ...  0
             延迟位       24位样本        补零
```

协议依据：[NXP UM11732 I²S specification，第3章](https://www.nxp.com/docs/en/user-manual/UM11732.pdf)。
32位时隙和24位数据是本工程的格式选择；实际DAC必须配置为匹配格式。

采样率公式：`Fs = Fclk / (2 × BCLK_HALF_DIV × 64)`。
默认 `BCLK_HALF_DIV=8`，要求输入 **49.152 MHz** 才能得到 **3.072 MHz BCLK / 48 kHz采样率**。
这只是本模块的时钟输入约定，尚未把开发板实际时钟配置成49.152 MHz。
如果直接输入50 MHz，采样率会变成48.828125 kHz，因此上板前必须核对并实现音频时钟方案。
测试台按名义49.152 MHz产生时钟；1 ps仿真精度会带来微小舍入，测试允许对应舍入误差。

`BCLK_HALF_DIV`必须大于等于1；测试同时覆盖默认8和边界值1。
当前未输出MCLK；若最终DAC需要MCLK，应由板级时钟模块提供，并核对它与采样率的关系。

## 缓冲、迟到与复位如何处理

- 缓冲可存两组完整的立体声样本，左右始终一起接收、一起出队。
- 满时ready拉低；若同一时钟恰好出队一组，则允许同时接收新的一组，不插入空闲拍。
- 空缓冲在帧边界恰好收到一组样本时，直接用于当前帧，不额外等待。
- 若帧开始仍无样本，本帧左右均输出零，不重复上一帧的数据。
- 晚于帧边界到达的样本留给下一帧，不允许左声道旧数据、右声道新数据。
- 在48 kHz下，两组缓冲最多引入约两个采样周期（41.67 us）的接收后排队等待；它不是整机演奏延迟。
- 复位清空队列、停止BCLK、清零串行数据和状态。释放复位后重新开始，旧样本不会漏出。

状态端口：

| 端口 | 意义 |
|---|---|
| fifo_level[1:0] | 等待输出的样本组数0～2，不包括正在发送的一帧 |
| underrun_pulse | 某帧缺样本，输出一个系统时钟脉冲 |
| underrun_sticky | 自复位以来是否曾经缺样本 |
| underrun_count[31:0] | 缺样本帧数，最大值饱和，不回绕；复位清零 |

启动时还没供样本也会计数，所以目前的测试会故意出现欠载。
实际演奏时应在稳定供数后记录计数增量。单拍脉冲若显示在LED上，需另做保持或拉长。

## 现在在 ModelSim 里怎么操作

在底部Transcript依次输入：

```tcl
cd {D:/your-workspace/git/TangMega60K_Synth/sim}
do waves_i2s.do
```

请将示例路径替换为本机实际目录。脚本编译、载入仿真、添加波形并运行110 us，随后放大到41～64 us。
不需要手动选择GW5AT仿真库，本阶段没有例化器件原语。

先看下面几项：

1. `sample_valid && sample_ready`：在系统时钟上升沿接收一组样本。
2. `bclk`：用于把样本一位一位传出去。
3. `ws`：低电平左声道，高电平右声道。
4. `data_out`：真正输出给DAC的数据位。
5. 第一组非零数据：左 `7fffff`、右 `800000`。解码完成后与 `expected_frame` 对比。
6. `underrun_count`：开始阶段故意不给样本，因此先增加；正常连续供数时应停止增加。

要放大某段时间，在Transcript使用：

```tcl
wave zoom range 41us 64us
```

查看已有全部波形用 `wave zoom full`。继续运行可用 `run 100 us`。
接收器的 `receive_word` 是逐位拼接的临时值，只有一个声道的24位都收齐后才是完整样本。
