## 2. 已交付的功能

| 功能 | 源码位置 | 核查说明 |
|---|---|---|
| 64 个逻辑声部 | `rtl/audio/voice_engine.v`、`voice_state_ram.v` | 默认 VOICE_COUNT=64，64×101 位状态；每个声部独立保存相位、基础频率、包络、力度和音色。运算硬件分时复用，并非复制 64 套物理乘法器。 |
| DDS 与实时变调 | `dds_lane.v`、`wavetable_rom.v` | 32 位相位，1024 点单周期波表，128 音符频率表，逐样本推进。 |
| ADSR 与完成通知 | `adsr.v`、`voice_engine.v` | Attack/Decay/Sustain/Release、释放结束后 done；输出受阻时完成通知保持稳定，逐声部 pending 记录完成。 |
| 两种音色 | `dds_lane.v`、`rom/waves.hex` | 正弦和含 1/2/3 次谐波的音色；编号 0/2 是同一类，1/3 是同一类，不能声称四种。尚未证明是真实钢琴等特定乐器的高保真音色。 |
| 三维表情运算 | `pitch_expression.v` | gain、bend、vibrato depth 真正参与音频计算；固定约 5 Hz LFO；每生成一帧更新一次平滑状态。 |
| 混音和限幅 | `stereo_mixer.v`、`gain_saturator.v` | 32 位累加、固定左右声像、宽位乘积、舍入、24 位饱和。 |
| 数字延迟 | `audio_fx.v` | 默认干声旁路；开启后 2400 样本，即 48 kHz 下 50 ms，反馈 0.5、湿声 0.25。并非混响或合唱。 |
| 完整 V2 音频连接 | `audio_system_v2.v` | 实例化主项目的 captain_system_top_v2 和 i2s_tx，提供干声和开启延迟两个顶层。 |
| 测试与资源证据 | `sim/tb_audio_*.sv`、`scripts/test-audio.ps1` 等 | 有单元测试、4/64 声部测试、I2S 串行解码核对、PCM 分析和综合脚本。 |

音频运行路径是 HDL 硬件逻辑。所查新增 RTL 未实例化软核 CPU/MCU，也未用软件播放 WAV/录音产生音源。PowerShell 只离线生成数学波表/比例表和分析仿真样本；`.hex` 是单周期波形与控制常量，不能等同于整段预录 PCM 播放。现有代码中用于 ROM 初始化的 `$readmemh` 已由本次 GOWIN 综合实现，不依赖上板后电脑持续计算音频。

本次重新生成的五份 ROM 与交付文件逐字节一致。每个含谐波的单波表声部仍按一个振荡器统计，不能把 64 声部乘以三个谐波声称 192 个独立振荡器。若实际板上 64 路同时活跃可闻、输出确为 48 kHz，对应吞吐目标为 3,072,000 振荡器样本/秒；现场条件仍需验证。

## 5. 不应误判为已经完成的内容

1. **25 键扫描和力度检测未完成。** A 的输入仍是 event 接口；没有键床矩阵扫描、双触点测时、去抖或 B 端事件 FIFO。
2. **延音踏板未完成。** ADSR 的 Sustain 状态不是踏板功能。当前分配器把仍 held 的同 `(source,note)` 再次按下视为重触发；仅扣住 note-off 并不能让同一键每次按下都新建声部。踏板、多次同音叠加和松踏板后的统一释放需共同设计，不能直接照聊天示意宣称已具备。
3. **没有独立全音停止/效果器清空协议。** 当前有复位，但不能把协调复位当作已完成产品化的 panic/mute 控制。延迟开启时把前级 gain 设为 0，已有回声仍会衰减发声。
4. **没有运行时效果器开关/旋钮协议。** FX_ENABLE 是静态参数；若只要求固定延迟效果，已具备算法。若要现场切换湿度、反馈或旁路，需另约接口。
5. **没有硬件常驻的 64 音自检按钮模式。** 64 个不同音高目前由仿真 testbench 注入，testbench 不会下载进 FPGA。现场测试需加入可综合事件发生器或约定外部控制方式。
6. **没有 PLL/CST/SDC 和最终板级顶层。** 两个 audio_system 顶层是连接示例，不能直接当整机烧录工程。未运行布局布线，不能由综合成功推出 Fmax、时序收敛或 I/O 电平正确。
7. **未证明端到端 ≤10 ms/≤5 ms。** 样本计算周期、10 ms ADSR Attack、50 ms 回声间隔是不同概念。应实际测量从物理按键/传感器动作到 DAC 输出开始响应的延迟，计入扫描、排队、缓存和 DAC。
8. **64 个谱峰现场验收仍需补充。** 4/64 声部 PCM 测试的满载段用了同音高；I2S 测试发送 MIDI 36..99 不同音高，但未生成独立“64 个可分辨谱峰”的通过判据。当前证明范围是逻辑声部运算和数字串行联调，不能替代板上频谱证据。
9. **完整三维物理交互、LED 曲目指引、蓝牙和录音回传不在 A 交付中。** 音源支持三参数，不等于外部传感器到声音的三维链路已经完成。

已知算法限制：高音加大弯音会夹紧在 0.45Fs；音色/力度突变与波表分区切换尚无交叉淡化；固定声像可能让每次分到不同声部的同音在左右位置上略变。上述均有代码依据，多数也在 A 文档披露，应在实际试听后确定是否调整。

## 7. 新发现的编译兼容问题

**[P2] `rtl/audio/stereo_mixer.v:10`、`:11` 使用 `strong` / `weak` 命名信号。** A 的 ModelSim `.do` 对 RTL 使用 Verilog 模式、对 testbench 使用 SystemVerilog 模式，所以可以通过；本次高云综合也通过。但如果按当前主项目 `scripts/test-iverilog.ps1` 的习惯把新增 RTL 与 testbench 一起交给 `iverilog -g2012`，上述名字会造成语法错误，第 16/17 行引用也报错。

复现：在隔离目录用 `iverilog -g2012 -s tb_audio_engine -Ptb_audio_engine.N=64` 编译新增 RTL 与音频测试台。此失败是混合语言模式的兼容问题，不是 V2 电气接口或音频计算错误。原有六组 Icarus 回归未包含新增音频 RTL，因此仍然通过。

建议 A 在正式源文件中把两个名字改成 `pan_strong`、`pan_weak`，并更新引用后补跑 Icarus。另一种方法是严格为 RTL 与 testbench 分别指定语言关键字版本。本次只在隔离目录生成带 `begin_keywords "1364-2005"` / `end_keywords` 的 include 包装文件，保留交付源码原样；使用包装文件的 Icarus 编译成功。额外 Icarus 64 声部运行耗时后主动停止，不计作仿真通过，也不据此判定 RTL 功能失败；音频功能验证以完成的 ModelSim 流程为准。这不等于已经修复正式交付。统一 SystemVerilog 编译失败的原始日志见隔离目录 `icarus_sv_compile_failure.log`。
