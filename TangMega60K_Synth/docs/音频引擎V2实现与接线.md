## 3. 接口连接示例

`audio_system_v2.v`是可直接编译的完整示例。信号方向相对于音频引擎如下：

```verilog
voice_engine u_engine (
    .clk(clk), .rst_n(rst_n),
    .cmd_valid(cmd_valid), .cmd_ready(cmd_ready),
    .cmd_on(cmd_on), .cmd_voice(cmd_voice),
    .cmd_note(cmd_note), .cmd_velocity(cmd_velocity), .cmd_timbre(cmd_timbre),
    .done_valid(done_valid), .done_ready(done_ready), .done_voice(done_voice),
    .sample_valid(sample_valid), .sample_ready(sample_ready),
    .sample_left(sample_left), .sample_right(sample_right),
    .engine_sample_begin(engine_sample_begin),
    .active_gain(active_gain),
    .active_bend_cents(active_bend_cents),
    .active_vibrato_cents(active_vibrato_cents)
);
```

- cmd和active参数由队长输出；cmd_ready由引擎输出。
- done与sample由引擎输出；对应ready由队长输出。
- begin由引擎输出。没有接到I2S的frame_tick，沒有新增source输入。
- `expr_applied`不是触发信号，不触发ADSR；它可用于调试。
- `sample_left/right`必须声明为signed 24位；bend必须声明为signed 13位。
- 采用同一个clk，协调复位。此工程没有跨时钟域FIFO。

## 4. 逐帧时序与反压

状态机：INIT -> IDLE -> 可选CMD_READ/CMD_WRITE -> PREP -> LATCH -> EXPR_WAIT -> 逐声部9拍 -> MASTER -> FX_SEND -> OUTPUT_WAIT。

PREP状态使begin为1，队长在该状态末尾的上升沿提交参数；下一个上升沿引擎处于LATCH，读取已更新的active参数。全局平滑器和LFO仅在LATCH推进一次。之后整帧使用固定的gain、pitch ratio。

每个声部9拍：读状态、算包络与频率乘积、截取频率、提交波表地址、等待ROM、包络乘法、力度乘法、左右累加、写回状态。没有64套并行振荡器。

输出反压期间，audio_fx的输出寄存器保持valid和左右样本；引擎停在OUTPUT_WAIT，不再次生成本帧，不推进任何相位、LFO或平滑器。独立done仲裁仍可工作；命令缓冲仍能接受一项命令。

每帧最多应用一条已接收的命令，防止事件流饿死音频计算。命令写RAM和声部写RAM从不并发。初始化用64拍逐项清RAM，不使用异步清零整个RAM的写法。

性能记录中的45/585拍，从begin提交沿统计到FX_SEND；不是整机传感器到DAC延迟。默认49.152 MHz/48 kHz每帧1024拍；实时I2S闭环另验证稳定供数。`BCLK_HALF_DIV=1`仍由原I2S回归覆盖，但本音源按默认DIV=8的预算设计，不宣称128拍内能完成64声部。

## 5. 合成与定点约定

- DDS：32位无符号相位，ROM地址取高10位；每声部每帧推进一次。FTW从128音符ROM读取。
- 波表：16位signed，1024点/周期。0和2为正弦别名；1和3为谐波音色别名。低音域使用4:2:1的1/2/3次谐波，较高音域减少到1/2次谐波，再高时只保留正弦。
- 谐波阈值：三谐波仅在基频<0.15Fs时使用，二谐波仅在<0.225Fs时使用；最终基频限制为<=0.45Fs。超过范围采用音高夹紧，**不保证极高音符+大弯音仍保持目标音高**。
- ADSR内部：24位无符号，1.0=0x800000；用于乘法的高16位对应1.0=32768。默认Attack=10 ms、Decay=80 ms，正弦Sustain=0.75，谐波音色Sustain=0.5。
- Release=100 ms指从满幅降到0的固定斜率；从0.75释放约75 ms，从更低值提前松键则更短。若需要“任意电平松键均精确100 ms”，需换成按释放起点计算步长的版本。
- 已活动声部重触发保留相位和当前包络，从当前位置进入ATTACK；新分配声部相位/包络从0开始。release不改力度、音色和基础频率。
- velocity：128项表，0映射0，127精确映射32768，使用Q1.15系数。乘包络和力度各使用33位signed完整乘积，右移15位时先加半LSB舍入（中点向正无穷）。
- 左右累加32位；默认偶数声部左3/4右1/4，奇数反向，可用PAN_SPREAD=0关闭固定声像。无动态声像接口。
- gain：12位无符号Q1.11，2048精确为1。先补零为13位有符号系数，乘积45位；右移11位舍入，再按MASTER_SHIFT=1转换尺度，最后饱和到24位。
- 默认缩放按64声部及gain<2留余量，与活动声部数无关，避免加减音符时其他声部音量跳变。单音相对满幅较小属于有意的保守余量，可在测量削波率后重新选择主增益。
- gain每帧最多变化8编码值，bend最多4音分，vibrato depth最多1音分；都能有限步数准确到达目标。gain=0不回收声部。
- 弯音：比例表Q3.20，范围-2500..2500整数音分；cents=0的比例精确为2^20。32×23位完整频率乘积保留55位并舍入。
- LFO：32位DDS、1024点正弦，FTW=round(5*2^32/Fs)。默认48 kHz为447392，对应约4.999995 Hz。深度转换成整数音分后与bend相加。

ROM随交付按48 kHz生成。若改变Fs，必须同时修改SAMPLE_RATE、重新生成FTW ROM及音频时钟方案；仅改RTL参数不足以改变既有ROM内容。无运行时real、sin、指数运算；浮点只存在于离线生成器和仿真/分析程序。

## 6. 反馈延迟与旁路

`voice_engine`默认FX_ENABLE=0，干声逐位透传。`audio_system_v2_delay`顶层开启FX_ENABLE=1：2400个样本、48 kHz时50 ms，反馈0.5、湿声系数0.25。

反馈写回：sat24(dry + delayed*feedback)。输出：sat24(dry + delayed*wet)。读写都使用同步时钟；缓冲未填满时旧内容被屏蔽，因此复位不泄漏旧回声。反馈配置限制在0..0.75；写回和输出均饱和。

audio_fx模块单独提供bypass端口：精确透传干声，冻结历史和指针。主引擎只通过静态FX_ENABLE选择，没有私自增加V2实时音效端口。再次启用模块旁路可能恢复历史尾音；若要实时无跳变切换，需要新控制协议和交叉淡化。

全局gain位于延迟输入之前：FX开启时将gain降至0会停止新干声进入，已有延迟尾音仍按反馈衰减。若产品要求包括回声在内立即静音，需要共同定义后级mute/clear效果器策略；默认FX旁路时gain=0严格静音。

## 7. 如何运行

在工程根目录的PowerShell执行：

```powershell
./scripts/test-audio.ps1 -ModelSimBin 'C:/modelsim/modeltech64_10.6e/win64'
```

脚本重新生成ROM，在新的临时目录编译，避免旧work库造成假通过；ModelSim运行单元测试、4声部、64声部、64声部I2S四组，再分析PCM。最终结果复制到`sim/audio_results/`。只要编译、运行、完成标志或PCM验收任一失败，就会报错。

ModelSim 10.6e在本机Tcl的glob路径枚举异常，因此.do使用显式源文件清单。临时编译目录路径会打印出来，便于排错；不自动删除它。

原队长六组回归：

```powershell
./scripts/test.ps1 -ModelSimBin 'C:/modelsim/modeltech64_10.6e/win64'
```

综合（从工程根目录）：

```powershell
& 'C:/Gowin/Gowin_V1.9.12_x64/IDE/bin/gw_sh.exe' scripts/synth-audio.tcl
# 另一次综合，开启延迟：
& 'C:/Gowin/Gowin_V1.9.12_x64/IDE/bin/gw_sh.exe' scripts/synth-audio-fx.tcl
```

两次综合使用同一个独立工程，后一次会覆盖impl中的报告。交付证据中分别保留dry/fx资源XML及日志。GOWIN界面中选择audio_system_v2（旁路）或audio_system_v2_delay（开启延迟）为顶层。

## 8. 已知边界与尚未完成项

1. V2未定义每声部连续音高目标/连奏规则，不能把新音符自动解释为旧声部滑音。本版实现全局弯音平滑；未虚构独立portamento接口。
2. V2无实时ADSR编辑、声像、delay wet/feedback/bypass协议，当前使用参数或音色预置。
3. 极高音符和上弯会触发0.45Fs夹紧。波表使用高位截断，没有插值；带限分表减少主要谐波混叠，不等于零杂散。跨分表阈值或重触发时突然改音色/力度，仍可能听到切换痕迹。
4. done表示该声部RELEASE结束；全局延迟尾音可以继续，不能等待全局回声结束才回收声部。
5. 新代码没有可比较的用户旧音源。中性兼容验收定义为：新核心关闭表情的固定参数路径，与V2中性参数路径逐位相等；不声称与不存在的旧音源逐位一致。
6. 完成的是RTL仿真和器件综合。尚无PLL、CST、板级复位、DAC配置、布局布线及SDC时序收敛，没有烧录，也没有实测音质、64谱峰可辨性或端到端延迟。
7. 未实现合唱/混响；这些本来属于延迟完成后的可选扩展。

具体实测数字和覆盖范围见`音频引擎V2验证记录.md`。
