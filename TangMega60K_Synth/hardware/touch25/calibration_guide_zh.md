# Touch25 R1 逐键校准工具

本工具为首板准备：读取真实采样CSV，为25键分别提出按下/松开阈值候选，并拦截缺测、通信故障、噪声与触摸范围重叠。工具已实现离线分析，**FPGA的MPR121采集驱动已接入完整工程，首板采样和校准仍待完成**。它不会写设备寄存器、修改Gerber或下载位流。

## 先固定再采集

先完成最终线束、模块底托及保护膜，再在这套装配条件下采集。改变线长、外壳、保护膜、供电或芯片滤波/采样配置后，重新采集完整数据；不同配置的日志不能混成一份校准记录。把本次装配照片和芯片配置读回值与CSV放在同一目录。

FPGA采集层应导出 `calibration_template.csv` 所列的列。可用后续驱动的串口或GAO记录转换，当前工程还没有自动导出此格式的硬件采集入口。万用表可核对供电、导通，不能提供这些寄存器样本。

| 列 | 内容 |
| --- | --- |
| sample_id | 捕获帧编号，同一模块/通道不得重复；各通道可共享同一帧号 |
| time_ms | 从捕获开始的非负整数毫秒，同一通道按CSV顺序严格递增；只是日志标记，不用于证明延迟 |
| environment | `amp_off`功放断电；`amp_on_idle`功放上电静音；`amp_on_loud`功放按正常最大演奏音量发声 |
| module / electrode | 模块1、2用ELE0–7；模块3用ELE0–8；填数字1–3和0–8 |
| phase | `idle`未触摸；`held`本键稳定按住；`released`本键松开并稳定；`neighbor`本键未触摸而邻键在触摸 |
| filtered | 从高低字节组合出的10位电极数据，0–1023 |
| baseline_raw8 | 基线寄存器原始8位值，0–255；不能预先乘4 |
| ack_ok | 该帧所需I²C事务均成功为1，否则0 |
| ovcf / oor / acff / arff | 过流、当前电极超范围、自动配置失败、自动重配置失败标志，0或1 |

按键稳定保持/松开的样本用于阈值分析；`held`包括希望识别的轻触和长按，不只采大面积指压；不要将过渡沿误标为稳定状态。每键在每个环境、每个phase至少记录30个不同的有效帧，采样间隔须与芯片真实更新节拍相符，不能反复读取同一旧帧凑数量。工具检查编号不重复和时间递增，但不能证明帧确为芯片新更新，采集驱动必须保证这一点。`neighbor`要包括附近容易误触的键、跨模块交界和实际手势；无需给未用通道编造数据。通信失败帧保留 `ack_ok=0`；无法读取的数值可填0占位，该帧不会参与阈值计算。

基线左移两位再与filtered比较：`delta_est = (baseline_raw8 << 2) - filtered`。基线未暴露的低两位使该估算可能少0–3个计数，工具因此给噪声上界补3个计数。MPR121为每电极提供按下与松开两个阈值，可形成滞回。[NXP AN3892](https://www.nxp.com/docs/en/application-note/AN3892.pdf)

## 运行和查看结果

把空模板复制为 `capture_r1_01.csv`，填入实测数据后运行：

```powershell
python hardware/touch25/calibrate_touch25.py hardware/touch25/capture_r1_01.csv --out hardware/touch25/calibration_r1_01.json
```

先停止采集并保存完整CSV，再运行分析。报告指纹与计算使用同一份字节快照。报告文件必须是新文件，工具拒绝覆盖旧报告。退出码0表示25键均形成候选；2表示至少一键缺测或不适合生成候选；1表示CSV格式/数据范围错误或文件读写错误。空模板会产生25键缺测报告，不会产生“校准完成”的结论。

报告逐键包含样本数量、故障帧、噪声上界、稳定触摸下界、寄存器地址和阈值候选。候选只使用本次日志观察到的极值与工程余量：先让松开阈值高于噪声上界，再令按下阈值低于稳定触摸下界，并保留滞回间隙。默认额外余量4计数是本项目启发式选择，**不是厂家规定值或统计可靠性保证**。可用 `--margin` 调整后重新验收。检测到任何故障帧的键不产生候选，先查接线、供电和芯片状态。

如果 `no_safe_threshold_gap`，先处理供电/接线干扰、重新固定模块、检查原始信号和芯片配置，不要强行把缺口压成一个阈值。白键、黑键和走线长度不同，逐键生成，不能直接假定25键共用同一阈值。

## 回写候选之后必须复测

由B的驱动在正确的停止/配置流程中写入候选并读回；确认三个模块只启用8/8/9个通道，状态掩码分别为`0x00FF / 0x00FF / 0x01FF`。工具不会代替完整初始化，配置流程见 [驱动交接](touch25_driver_handoff_zh.md)。

逐键反复按下/松开、轻触和长按，再测邻键、双键/四键和跨模块和弦；松开一键时其他键仍应保持。至少分别测试功放断电、上电静音、正常演奏音量，以及重新上电无手触碰时的基线建立。用另一轮独立日志和实物事件检查复测，不能拿同一训练日志当验收通过。

滤波、采样间隔、消抖与I²C排队都会影响完整响应。工具不从稳定态采样推算触摸到声音的延迟；需要另做端到端测量。[NXP AN3890](https://www.nxp.com/docs/en/application-note/AN3890.pdf)

## 工具自身验证

```powershell
python hardware/touch25/test_calibrate_touch25.py
```

测试使用明确的合成数据，覆盖25键映射、基线量纲、ELE8寄存器、缺测、通信/传感器故障、噪声重叠、阈值位宽、重复帧、时间递增、无效通道、指纹一致性和报告覆盖保护。通过只证明离线算法的这些行为，不能代表触摸硬件或延迟已实测。
