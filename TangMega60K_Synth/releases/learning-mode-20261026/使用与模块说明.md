# 按对才前进的学习模式

这是独立于原来“按节奏亮灯”的新模式。FPGA读取实体25键的触摸状态，等待当前目标；不靠电脑定时器推进，不播放预录音频。

## 怎么用

1. 在Gowin Programmer中选择 `SRAM Program`，下载本次交付的 `ContestFull_LearningMode1024.fs`。旧位流没有学习判定逻辑。断电后SRAM程序会丢失。
2. 打开本次 `delivery-learning-mode/windows/TangNeonStudio/TangNeonStudio.exe`，左下角版本是 **1.5.0**；保留同目录的 `_internal`。
3. 连接设备，在曲谱页选择**内置曲谱或25键映射曲谱**。直接音高播放和蓝牙实时曲谱不支持实体25键学习。
4. 回到“演奏”页，在灯位图旁点击 **等我弹对**。程序先选择/上传正确曲谱，再启动学习。
5. 先松开全部琴键，再按绿色目标。比如“03 + 05 + 08号键”表示同时按住这三个编号的实体键。
6. 再点 **停止学习** 停止提示；“全部停止”还会释放声音。原来的“灯光指引”仍按曲谱节奏前进，不等待。

没接硬件可以先进入“离线演示”，使用电脑琴键体验流程；这是模拟，不代表实物已通过测试。真实连接时，电脑/蓝牙发出的音符**不能替代实体琴键过关**。

## 判定规则

- 没按键就一直等，没有超时跳过。
- 正确键要全部按齐，不能额外按错键；和弦可先后落指，只要最终同时按住目标组合即可。
- 每组开始前必须松开所有键，连续两个相同音也要重新按，避免长按自动过关。
- 一个“学习步骤”对应同一时间戳的有效NoteOn组合；后续 `deltaMs=0` 的按键属于同一组。NoteOff和力度为0的NoteOn不成为新目标。
- 本版练习的是**找键与和弦**，不考核拍子、按住时长、力度或实际声音的音准。原谱中的连奏、延音暂简化为每组先松开。
- 三组触摸传感器均须就绪且无故障。故障时停止过关，恢复后重新要求松开。
- 只取消学习提示不会代替用户松键。正常触摸发声、包络释放仍走原有通路。
- 屏幕目标来自FPGA状态；约150ms空闲轮询更新，通信忙则跳过，不积累查询。屏幕可能慢于实体灯。3秒没有新学习状态时清除屏幕高亮并提示等待回传。
- 学习核心可以独立运行，不依赖电脑前台；但软件主动断开连接、全部停止、复位等已有操作可能会停止学习。不要把“断开”作为保留学习的操作。

## 模块怎样分工

| 文件 | 职责 |
|---|---|
| `rtl/performance/learning_stepper.v` | 收集当前音符组、等待松键、判断是否按齐、统计完成步数；可综合状态机 |
| `rtl/performance/performance_controller.v` | 管理曲谱RAM及开始/停止，给学习器顺序提供事件；与原定时播放器共用读口 |
| `rtl/control/remote_command_router.v` | 接受学习命令，读取并缓存状态快照；处理重试、反压 |
| `rtl/instrument_full_system.v` | 接入真实触摸状态；学习目标送到原有25灯指引驱动 |
| `full/ContestFull.gprj` | 增加学习器源文件；原引脚、时钟和时序约束不变 |
| `desktop/web/learning-control.js` | Windows学习会话、旧固件识别、上传前检查、取消与空闲轮询 |
| `desktop/web/learning-demo.js` | 离线演示模型，不参与实物音频或判定 |
| `desktop/web/protocol.js`、`controller.js` | 定义新状态格式、请求与解析；保留既有演奏请求队列 |
| `desktop/web/guide-panel.js`、`app.js`、`index.html` | 按钮、键号、完成步数、缺少状态时的提示 |
| `sim/tb_learning_*.sv` | 学习状态机、协议反压/重试、完整UART链路测试 |
| `desktop/tests/test_learning*.cjs` | 协议业务与浏览器界面测试 |
| `scripts/verify-learning-mode.ps1` | 隔离复制、ModelSim回归及可选高云构建 |

音频合成、音色、ADSR、I2S、手机程序、C3固件均未改动。学习器复用原来的1024条曲谱RAM，不复制PCM或整首曲谱。

## 协议扩展

固定16字节帧、CRC、ACK和原有命令保持不变；未改公共V2 `event_* / cmd_* / done_* / sample_*`。

- `TRANSPORT(0x04)` payload byte0=`9`：开始学习，其余字节为0。忙碌返回2，直接音高曲谱返回1。旧固件不支持9。
- 动作7：停止所有指引（包括学习）；0/5也会停止学习。现有本地停止指引操作同样生效。
- `READBACK(0x08)` selector=`4`、index=0：ACK后返回 `0x85`，新序号读取新快照；相同序号重试仍返回缓存快照。
- 旧固件对selector4返回NACK。Windows先探测，失败时不给旧固件发学习启动，也不偷偷改成自动播放。

| 0x85 payload字节 | 内容 |
|---|---|
| 0 | 格式版本1 |
| 1 | bit0=支持学习；bit1=运行；bit2=等松键；bit3=等按对；bit4=完成；bit5=传感器就绪 |
| 2–3 | 已完成步骤数，小端16位 |
| 4–7 | 当前目标，小端32位，仅低25位有效；bit0对应编号01 |
| 8–9 | 曲谱读取位置，小端16位；不是完成步骤数，也不是剩余秒数 |

收集下一组时可能短暂“运行中但目标为0”。状态查询不会修改学习进度；BLE桥按原方式透明转发，无需更新C3固件。

## 验证与限制

运行命令（在 `TangMega60K_Synth` 根目录的PowerShell中）：

```powershell
./scripts/verify-learning-mode.ps1 -Build
node desktop/tests/test_learning.cjs
node desktop/tests/test_learning_ui.cjs
```

脚本需本机已安装ModelSim、高云IDE和项目Python；可用参数指定工具路径。ModelSim 10.6不适应中文路径，脚本先复制到英文临时目录，记录输入哈希并保留日志。构建关闭的是快照内GAO在线探针，原有约束不放宽，不扫描或下载板卡。

最终实际测试次数、资源和时序以交付目录中的 `验证结果.md`、原始日志及JSON为准，不能仅凭位流文件存在认为通过。UART集成测试在触摸采集边界注入状态，未模拟手指电容或实物灯板。

**待实测：** 新位流下载、实体25键、实际BLE往返、5×5灯板型号/顺序/旋转方向，以及长时间稳定性。灯位编号和贴纸沿用既有方案；灯板没到，不能声称已逐灯对齐。OLED沿用现有页面，不新增逐音学习文字。

旧版可执行程序和旧位流保留在原交付目录。本次不推送远端，不自动给板卡下载。
