# 蓝牙连接与 ACK 定位改进（2026-10-23）

已完成 C3 重连修复、电脑端 1.0.4 分层诊断，以及当前硬件上的固件更新和只读查询。
**真实 FPGA ACK 仍未收到，不能把本轮软件测试通过等同于蓝牙钢琴已连通。**

## 修改与验证

- C3 的错误关闭请求改为交给 NimBLE host task 执行，在该任务中核对完整失败会话代际。
  避免旧连接的迟到错误误关新连接，包括连接句柄被复用的情况。
  实际 sketch 的确定性生命周期测试修后 62/62 通过；修前新增 6 项中有 3 项失败。
  实际 sketch 与选中 SDK WRITE 处理器的接收回归 60/60 通过。
- 电脑端 1.0.4 在 BLE 订阅后保存可选 DIAG004 基线，断开前采集差值。
  每次只读采集上限 0.75 秒；缺少特征、格式未知、超时均不阻断兼容设备。
  保留原 ACK 错误、立即关闭协议会话，不增加协议超时、不伪造 ACK。
  无基线时只显示累计值；旧代际结果不覆盖新连接，正常断开不误报握手失败。
  新原生诊断 11 项、原有原生通信 11 项、实际界面定向 3 项和完整静音界面回归通过。
  新 EXE 内的实际代码也经过提取校验与回归。
- FPGA 本轮未改 RTL。81 个主工程输入与完整已构建位流逐项匹配。
  下载后用户码为 **8FE0**；**6D50 是 GAO 配置标识，不是位流用户码**。

本轮未改 UART 引脚、电平、波特率或 16 字节协议。
SDK UART 错误回调没有事件源会话标签，延迟旧 UART 错误仍可能归属执行时会话；
本轮保留原有失败关闭策略，未用忽略错误的方式掩盖问题。当前实机错误计数均为 0，
没有证据把这个边界认定为本次 ACK 超时根因。

## 已在硬件执行的操作

1. C3 身份与原固件备份确认：MAC `90:e5:b1:6c:2a:4c`，ESP32-C3，4 MB。
   两次连续读取因 USB 短包失败；随后分段读取成功，应用区逐字节匹配 10 月 22 日旧固件。
   完整备份保存在本机 `c3-backup-segmented-20261023_220901/`，未纳入交付压缩包。
   各分段读取之间有复位，因此这不是可变 NVS 的原子快照。
2. 新 C3 仅写应用区 `0x10000`。写入哈希校验与独立 `verify-flash` 摘要均匹配。
   应用 SHA-256：`a4d215aadbf5bbc93f7a5ef0bf33a38e42301b31b30932c60cd651001943b388`。
3. DEBUG 数据线重新连接后识别到 FPGA。当前用户码原为 A937，完整主工程已下载到 SRAM，
   读回用户码 8FE0。没有写非易失 Flash；断电后可能恢复原启动程序。
4. 多次只读 READBACK 与实际新版 NativeHost 诊断结果一致：
   每次 C3 报告 BLE 收帧 +1、UART 提交 +1、UART 返回字节 +0、有效响应帧 +0、通知接受 +0。
   同序号 ACK、telemetry 均未收到。这里“UART 提交”是 C3 驱动完成报告，
   不单独证明物理引脚波形、接线或 FPGA 收到了命令。

FPGA 内部时钟、复位、UART 接收/发送状态仍需要片内采样或物理波形继续定位。
本机官方分析器帮助只提供图形采样启动方式；本轮未取得 GAO 硬件采样数据。
不要仅凭更新完成或蓝牙连接成功宣称整个握手修复。
